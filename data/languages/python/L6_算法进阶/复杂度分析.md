# L6 算法进阶：复杂度分析

## 1. 本课目标

- 能看懂 `O(1)、O(logn)、O(n)、O(nlogn)、O(n²)` 这些常见复杂度，并判断一段简单代码大致属于哪一种。
- 会分析“循环、嵌套循环、二分、排序、递归”的时间复杂度和额外空间复杂度。
- 能根据数据量做粗略选择：例如 `n` 到 `10^5` 时，优先考虑 `O(n)` / `O(nlogn)`，避免明显的 `O(n²)`。

---

## 2. 概念讲解

### 2.1 复杂度不是“运行几秒”，而是“增长趋势”

同一段代码，在不同电脑上运行时间可能不同。复杂度研究的是：

> 当输入规模 `n` 变大时，操作次数大约怎么增长？

比如：

- 列表长度从 100 变成 1000，`O(n)` 的循环大约多做 10 倍工作。
- `O(n²)` 的双层循环大约多做 100 倍工作。
- `O(logn)` 的二分查找只多几步，因为每一步都能把范围砍掉一半。

打比方：  
`O(1)` 像“直接问前台第 1 个房间在哪”；  
`O(n)` 像“从第 1 个房间挨个找”；  
`O(n²)` 像“每个人都去和所有人逐一握手”；  
`O(logn)` 像“每次都把可能范围缩小一半”。

### 2.2 大 O 表示法：忽略常数和低阶项

如果操作次数是：

```text
3n² + 100n + 50
```

当 `n` 很大时，真正决定增长趋势的是 `n²`。所以我们写成：

```text
O(n²)
```

大 O 会忽略：

- 常数：`3n` 和 `100n` 都记作 `O(n)`；
- 低阶项：`n² + n` 记作 `O(n²)`。

为什么可以忽略？因为当 `n` 从 1 万变成 100 万时，`n²` 的影响会远远超过常数和 `n`。

### 2.3 常见复杂度从快到慢

| 复杂度 | 直观含义 | 常见例子 |
|---|---|---|
| `O(1)` | 常数时间 | 取列表首元素、`set` 平均查找 |
| `O(logn)` | 每次砍一半 | 二分查找 |
| `O(n)` | 扫一遍 | 求和、Kadane 最大子数组和 |
| `O(nlogn)` | 排序级别 | `sorted()`、归并排序、快速排序平均 |
| `O(n²)` | 两两组合 | 双层循环、暴力两数之和 |
| `O(2^n)` | 指数爆炸 | 无缓存递归斐波那契、枚举所有子集 |

粗略经验：

- `n <= 10^5`：`O(nlogn)` 通常可以接受；
- `O(n²)` 在 `n = 10^5` 时大约是 `10^10` 次操作，通常会超时；
- `O(2^n)` 在 `n = 30` 左右就可能非常慢。

### 2.4 时间复杂度和空间复杂度

- **时间复杂度**：操作次数随 `n` 怎么增长。
- **空间复杂度**：除了输入本身外，额外开辟了多少存储空间。

注意：

- 新建一个长度为 `n` 的列表或字典：通常 `O(n)` 额外空间；
- 只用了几个变量：`O(1)` 额外空间；
- 递归调用占用的调用栈也要算空间。例如递归深度为 `n`，空间通常至少 `O(n)`。

Kadane 最大子数组和只用了几个变量，所以是 `O(n)` 时间、`O(1)` 额外空间；爬楼梯用滚动变量实现，也是 `O(n)` 时间、`O(1)` 空间。

### 2.5 怎么快速看代码复杂度

1. **单层循环**：通常 `O(n)`。
2. **两层嵌套循环**：通常 `O(n²)`；如果内层只跑固定次数，则仍可能是 `O(n)`。
3. **循环变量每次乘 2 或除以 2**：通常出现 `O(logn)`。
4. **先排序再二分**：排序 `O(nlogn)`，二分 `O(logn)`。
5. **递归**：看每层分裂成几次调用、递归深度是多少。分治常见到 `T(n)=2T(n/2)+O(n)`，结果是 `O(nlogn)`，现在先认识即可，不要求推公式。
6. **小心内置操作**：`x in list` 是 `O(n)`，`x in set` 平均 `O(1)`；`list.pop(0)` 是 `O(n)`，`list.append()` 摊还 `O(1)`。

## 3. 由浅入深的完整示例

### 示例 1：`O(1)` 和 `O(n)`——输入变大时，谁的操作次数变多？

```python
# 例1：O(1) 和 O(n) 的对比
# 说明：这里的 steps 是“基本操作次数模型”，不是实际秒数。
# 大 O 忽略常数，所以首元素访问记作 1 次，求和循环记作 n 次。

def first_item(arr):
    return arr[0]

def sum_loop(arr):
    total = 0
    for x in arr:
        total += x
    return total

for n in [10, 100, 1000]:
    arr = list(range(n))

    steps_first = 1   # 首元素访问：常数次
    steps_sum = n     # 求和：循环 n 次

    print(f"n={n:4d} | first_item 约为 O(1): {steps_first} 步 | sum_loop 约为 O(n): {steps_sum} 步")

    # 实际调用一次，保证代码确实运行
    assert first_item(arr) == 0
    assert sum_loop(arr) == n * (n - 1) // 2

# 预期输出：
# n=  10 | first_item 约为 O(1): 1 步 | sum_loop 约为 O(n): 10 步
# n= 100 | first_item 约为 O(1): 1 步 | sum_loop 约为 O(n): 100 步
# n=1000 | first_item 约为 O(1): 1 步 | sum_loop 约为 O(n): 1000 步
```

观察重点：`n` 从 10 到 1000 翻了 100 倍，`O(n)` 的步数也大约翻 100 倍；`O(1)` 的步数不变。

### 示例 2：同一道题，`O(n²)` 和 `O(n)` 的差距

```python
# 例2：两数之和
# 同一个任务：
# 1. 暴力法：两层循环，O(n²)
# 2. 哈希表：边遍历边记录，平均 O(n)

def two_sum_bruteforce(nums, target):
    steps = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            steps += 1
            if nums[i] + nums[j] == target:
                return (i, j), steps
    return None, steps

def two_sum_hash(nums, target):
    steps = 0
    seen = {}  # 值 -> 下标，字典查找平均 O(1)
    for i, x in enumerate(nums):
        need = target - x
        steps += 1
        if need in seen:
            return (seen[need], i), steps
        seen[x] = i
    return None, steps

nums = list(range(101))  # [0, 1, 2, ..., 100]
target = 199             # 99 + 100 = 199，答案位置比较靠后

ans1, steps1 = two_sum_bruteforce(nums, target)
ans2, steps2 = two_sum_hash(nums, target)

print("暴力答案:", ans1, "比较次数:", steps1)
print("哈希答案:", ans2, "查找次数:", steps2)
print("说明: n 越大，暴力法的比较次数约按 n² 增长；哈希法约按 n 增长。")

# 预期输出：
# 暴力答案: (99, 100) 比较次数: 5050
# 哈希答案: (99, 100) 查找次数: 101
# 说明: n 越大，暴力法的比较次数约按 n² 增长；哈希法约按 n 增长。
```

注意：哈希法把时间复杂度从大约 `O(n²)` 降到了平均 `O(n)`，但付出了额外空间：字典最多保存 `n` 个元素，所以空间复杂度是 `O(n)`。

### 示例 3：线性查找和二分查找，`O(n)` 与 `O(logn)`

```python
# 例3：在有序数组中查找目标值
# 线性查找：从头到尾扫，O(n)
# 二分查找：每次把范围砍一半，O(logn)

def linear_search_steps(arr, target):
    for i, x in enumerate(arr):
        if x == target:
            return i, i + 1
    return -1, len(arr)

def binary_search_steps(arr, target):
    left, right = 0, len(arr) - 1
    steps = 0
    while left <= right:
        steps += 1
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid, steps
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1, steps

for n in [10, 100, 1000, 10000]:
    arr = list(range(n))
    target = n - 1  # 放在最后，让线性查找多扫一些

    idx_lin, s_lin = linear_search_steps(arr, target)
    idx_bin, s_bin = binary_search_steps(arr, target)

    print(f"n={n:5d} | 线性: idx={idx_lin:5d}, 步数={s_lin:5d} | 二分: idx={idx_bin:5d}, 步数={s_bin:2d}")

# 预期输出：
# n=   10 | 线性: idx=    9, 步数=   10 | 二分: idx=    9, 步数= 4
# n=  100 | 线性: idx=   99, 步数=  100 | 二分: idx=   99, 步数= 7
# n= 1000 | 线性: idx=  999, 步数= 1000 | 二分: idx=  999, 步数=10
# n=10000 | 线性: idx= 9999, 步数=10000 | 二分: idx= 9999, 步数=14
```

二分查找有一个前提：数组必须已经有序。  
如果数组本身无序，先排序需要 `O(nlogn)`，再二分是 `O(logn)`。如果只查一次，可能不如直接 `O(n)` 扫一遍；如果要查很多次，排序后二分通常更划算。

## 4. 常用函数/调用速查表

| 函数/写法 | 签名/示例 | 用途 | 最小示例 |
|---|---|---|---|
| `len(x)` | `len(seq)` | 获取长度，通常 `O(1)` | `len([1, 2, 3])` → `3` |
| `list.append(x)` | `lst.append(x)` | 尾部追加，摊还 `O(1)` | `a=[1]; a.append(2); a` → `[1, 2]` |
| `list.pop()` | `lst.pop()` | 弹出末尾元素，`O(1)` | `[1, 2, 3].pop()` → `3` |
| `list.pop(0)` | `lst.pop(0)` | 弹出头部，后面元素要前移，`O(n)` | `[1, 2, 3].pop(0)` → `1` |
| `x in list` | `x in lst` | 列表查找，最坏 `O(n)` | `2 in [1, 2, 3]` → `True` |
| `x in set` | `x in s` | 集合查找，平均 `O(1)` | `2 in {1, 2, 3}` → `True` |
| `x in dict` | `x in d` | 字典查键，平均 `O(1)` | `2 in {1: 'a', 2: 'b'}` → `True` |
| `set.add(x)` | `s.add(x)` | 加入集合，平均 `O(1)` | `s=set(); s.add(2); s` → `{2}` |
| `sorted(x)` | `sorted(iterable)` | 返回排序后的新列表，通常 `O(nlogn)` | `sorted([3, 1, 2])` → `[1, 2, 3]` |
| `list.sort()` | `lst.sort()` | 原地排序，通常 `O(nlogn)` | `a=[3,1,2]; a.sort(); a` → `[1, 2, 3]` |
| `bisect_left` | `bisect_left(arr, x)` | 有序列表中二分找位置，`O(logn)` | `from bisect import bisect_left; bisect_left([1,3,5], 3)` → `1` |
| `math.log2(n)` | `math.log2(n)` | 计算以 2 为底的对数，帮助理解 `logn` | `import math; math.log2(8)` → `3.0` |

## 5. 五个新手易错点

### 易错点1：空列表直接取 `nums[0]`，边界没处理

❌ **错误写法**

```python
# 错误：没有检查空输入，分析 O(1) 访问时忽略了边界情况
def get_first(nums):
    return nums[0]

print(get_first([10, 20]))  # 正常时能输出 10
print(get_first([]))        # 空列表仍然直接访问 [0]

# 运行报错：IndexError: list index out of range
```

✅ **正确写法**

```python
# 正确：O(1) 访问之前，先保证输入非空
def get_first(nums):
    if not nums:
        return None
    return nums[0]

print(get_first([10, 20]))  # 10
print(get_first([]))        # None
```

为什么错：`O(1)` 只说明操作次数是常数级，不代表对任何输入都安全；复杂度分析里的最坏情况必须覆盖空输入、单元素、越界等边界。

---

### 易错点2：在循环里用 `list` 查重，隐藏成 `O(n²)`

❌ **错误写法**

```python
# 错误：用 list 的逐项查找来查重，外层 for + 内层扫描，隐藏 O(n²)
def has_duplicate_with_list(nums):
    seen = []
    steps = 0
    for x in nums:
        steps += 1
        for y in seen:
            steps += 1
            if y == x:
                return True, steps
        seen.append(x)
    return False, steps

nums = list(range(200)) + [0]
found, steps = has_duplicate_with_list(nums)

if not found:
    raise AssertionError("数据里应当有重复元素")
if steps > len(nums):
    raise AssertionError("使用 list 逐项查找会超过线性预算")

# 运行报错：AssertionError: 使用 list 逐项查找会超过线性预算
```

✅ **正确写法**

```python
# 正确：用 set 记录已经见过的元素，平均 O(1) 查找
def has_duplicate_with_set(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False

nums = list(range(200)) + [0]
print(has_duplicate_with_set(nums))  # True
```

为什么错：`x in list` 最坏要扫一大截，把它放进 `for` 里就隐藏成 `O(n²)`；查重、查表优先考虑 `set` / `dict` 的平均 `O(1)` 查找。

---

### 易错点3：无缓存递归斐波那契，指数时间 + 递归栈

❌ **错误写法**

```python
# 错误：无缓存递归斐波那契，n 稍大就会大量重复计算，并触发递归深度限制
def bad_fib(n):
    if n <= 1:
        return n
    return bad_fib(n - 1) + bad_fib(n - 2)

print(bad_fib(2000))

# 运行报错：RecursionError（maximum recursion depth exceeded）
```

✅ **正确写法**

```python
# 正确：用两个滚动变量迭代计算，O(n) 时间，O(1) 额外空间
def good_fib(n):
    if n <= 1:
        return n
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b

print(good_fib(10))  # 55
print(good_fib(20))  # 6765
```

为什么错：无缓存递归会重复计算大量子问题，时间复杂度接近指数级，递归调用栈还会占空间；能看出递推关系时，用循环或缓存把问题降成 `O(n)`。

---

### 易错点4：把冒泡排序当 `O(nlogn)`，嵌套循环仍是 `O(n²)`

❌ **错误写法**

```python
# 错误：冒泡排序是 O(n²)，不是排序了就自动 O(nlogn)
def bubble_sort_count(arr):
    a = arr[:]
    comparisons = 0
    for i in range(len(a)):
        for j in range(len(a) - i - 1):
            comparisons += 1
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
    return a, comparisons

data = list(range(30, 0, -1))
sorted_data, comparisons = bubble_sort_count(data)

if comparisons > len(data) * 5:
    raise AssertionError("冒泡排序的比较次数超过线性预算")

# 运行报错：AssertionError: 冒泡排序的比较次数超过线性预算
```

✅ **正确写法**

```python
# 正确：日常优先使用 Python 内置 sorted / list.sort()
data = list(range(30, 0, -1))
sorted_data = sorted(data)

print(sorted_data[:5])  # [1, 2, 3, 4, 5]
print(sorted_data[-1])  # 30
```

为什么错：冒泡排序是典型的 `O(n²)`，不能因为代码能排好序就忽略增长趋势；大多数场景应优先使用 `sorted()` / `list.sort()`，通常按 `O(nlogn)` 量级理解。

### 易错点5：二分查找右边界写成 `len(arr)`，导致越界

❌ **错误写法**

```python
# 错误：闭区间 [left, right] 中 right 应该是 len(arr)-1
def binary_search_bad(arr, target):
    left, right = 0, len(arr)  # 错在这里
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

print(binary_search_bad([1, 3, 5], 6))

# 运行报错：IndexError: list index out of range
```

✅ **正确写法**

```python
# 正确：闭区间写法，right 从 len(arr)-1 开始
def binary_search_good(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

arr = [1, 3, 5, 7, 9]
print(binary_search_good(arr, 7))  # 3
print(binary_search_good(arr, 6))  # -1
```

为什么错：二分查找每一步把区间减半才是 `O(logn)`，但边界写错会直接越界；使用闭区间 `[left, right]` 时，初始右边界必须是 `len(arr) - 1`。

def max_sub_array(nums):
    if not nums:
        return 0
    current_max = global_max = nums[0]
    for num in nums[1:]:
        current_max = max(num, current_max + num)
        global_max = max(global_max, current_max)
    return global_max

## 7. 本课小结

- 大 O 描述的是输入规模变大时的增长趋势，忽略常数和低阶项；`3n² + 100n` 记作 `O(n²)`。
- 看到单层循环先想 `O(n)`，看到双层嵌套先想 `O(n²)`，看到每次砍半先想 `O(logn)`，看到排序先想 `O(nlogn)`。
- 空间复杂度只算额外空间；递归调用栈、新建的列表/集合/字典都要算进去。
- 内置操作也有成本：`x in list` 是 `O(n)`，`x in set/dict` 平均 `O(1)`，`sorted` 通常是 `O(nlogn)`。
- 做题前先看数据量：`n` 到 `10^5` 时，明显 `O(n²)` 的方案通常要改成 `O(n)` 或 `O(nlogn)`。
