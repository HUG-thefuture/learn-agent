# 📦 L3 工程能力：虚拟环境与包管理

## 🎯 本课目标

1. **理解虚拟环境的作用**：学会创建和激活虚拟环境，隔离不同项目的依赖。
2. **掌握 pip 包管理**：能安装、卸载、查看和管理 Python 第三方包。
3. **学会使用 requirements.txt**：能导出和导入项目依赖，方便团队协作和部署。

---

## 🧠 概念讲解

### 1. 什么是虚拟环境？

> 📌 **虚拟环境**就像给每个项目准备一个独立的"工具箱"。每个工具箱里都有自己的一套工具（Python 包），互不干扰。

**为什么需要虚拟环境？**

想象你同时开发两个项目：
- 项目 A 需要 `requests` 库的 2.0 版本
- 项目 B 需要 `requests` 库的 3.0 版本

如果都装在全局环境里，就会冲突。虚拟环境让每个项目有自己的"小天地"。

### 2. 什么是 pip？

> 📌 **pip** 是 Python 的"应用商店"，用来安装、卸载和管理第三方包。

就像手机上的应用商店，你可以：
- 搜索包：`pip search 包名`
- 安装包：`pip install 包名`
- 卸载包：`pip uninstall 包名`
- 查看已安装：`pip list`

### 3. 什么是 requirements.txt？

> 📌 **requirements.txt** 是一个文本文件，记录了项目所有依赖包的名称和版本。

就像超市购物清单，别人拿到这份清单，就能一键安装所有需要的包。

## 💻 完整示例

### 示例 1：创建和使用虚拟环境

```python
# 这个示例展示虚拟环境的基本概念（在命令行中操作）
# 注意：以下命令需要在终端/命令行中执行，不是在 Python 代码中

# 1. 创建虚拟环境（在项目目录下）
# python -m venv myenv

# 2. 激活虚拟环境
# Windows: myenv\Scripts\activate
# Mac/Linux: source myenv/bin/activate

# 3. 在虚拟环境中安装包
# pip install requests

# 4. 查看已安装的包
# pip list

# 5. 退出虚拟环境
# deactivate

# 预期输出：在终端中看到虚拟环境名称前缀，如 (myenv) C:\Users\...>
```

### 示例 2：使用 pip 管理包

```python
# 这个示例演示 pip 的常用命令（在命令行中执行）
# 注意：以下命令需要在终端/命令行中执行

# 1. 安装包（安装最新版本）
# pip install requests

# 2. 安装指定版本
# pip install requests==2.28.1

# 3. 升级包
# pip install --upgrade requests

# 4. 卸载包
# pip uninstall requests

# 5. 查看包信息
# pip show requests

# 预期输出：显示包的版本、位置、依赖等信息
```

### 示例 3：使用 requirements.txt 管理依赖

```python
# 这个示例演示如何导出和导入依赖（在命令行中执行）

# 1. 导出当前环境的依赖到文件
# pip freeze > requirements.txt

# 2. 查看 requirements.txt 内容
# type requirements.txt  (Windows)
# cat requirements.txt   (Mac/Linux)

# 3. 在新环境中安装所有依赖
# pip install -r requirements.txt

# 预期输出：
# requirements.txt 内容示例：
# requests==2.28.1
# flask==2.2.2
# numpy==1.23.5
```

## ⚠️ 新手易错点

### 易错点1：忘记激活虚拟环境

❌ **错误写法**：
```python
# 创建了虚拟环境但没激活，直接安装包
# 在终端中执行：
# python -m venv myenv
# pip install requests  # 这会安装到全局环境！

# 运行报错：包安装到了全局环境，虚拟环境里没有
# 检查方式：pip list 看不到 requests
```

✅ **正确写法**：
```python
# 先激活虚拟环境再安装
# 在终端中执行：
# python -m venv myenv
# source myenv/bin/activate  # Mac/Linux
# myenv\Scripts\activate     # Windows
# pip install requests       # 现在安装到虚拟环境了

# 验证：pip list 能看到 requests
# 预期输出：requests 出现在已安装包列表中
```

**为什么错**：不激活虚拟环境，pip 默认安装到全局环境，导致依赖混乱。

---

### 易错点2：在虚拟环境外运行项目

❌ **错误写法**：
```python
# 创建了虚拟环境并安装了包，但运行时没激活
# 在终端中执行：
# python -m venv myenv
# source myenv/bin/activate
# pip install requests
# deactivate  # 退出虚拟环境
# python my_script.py  # 运行脚本

# 运行报错：ModuleNotFoundError: No module named 'requests'
```

✅ **正确写法**：
```python
# 保持虚拟环境激活状态运行
# 在终端中执行：
# python -m venv myenv
# source myenv/bin/activate
# pip install requests
# python my_script.py  # 在激活状态下运行

# 预期输出：脚本正常运行，能导入 requests
```

**为什么错**：退出虚拟环境后，Python 找不到虚拟环境里安装的包。

---

### 易错点3：直接修改全局环境

❌ **错误写法**：
```python
# 不使用虚拟环境，直接全局安装包
# 在终端中执行：
# pip install flask

# 问题：所有项目共享这个包，版本冲突风险高
# 如果项目A需要flask 1.0，项目B需要flask 2.0，就会冲突
```

✅ **正确写法**：
```python
# 每个项目创建独立虚拟环境
# 在终端中执行：
# mkdir project_a && cd project_a
# python -m venv venv
# source venv/bin/activate
# pip install flask==1.0

# mkdir project_b && cd project_b
# python -m venv venv
# source venv/bin/activate
# pip install flask==2.0

# 预期输出：两个项目互不干扰，各自使用自己的flask版本
```

**为什么错**：全局环境共享会导致版本冲突，虚拟环境隔离了依赖。

---

### 易错点4：忘记更新 requirements.txt

❌ **错误写法**：
```python
# 安装了新包但没更新 requirements.txt
# 在终端中执行：
# source myenv/bin/activate
# pip install pandas
# # 忘记执行 pip freeze > requirements.txt

# 问题：别人克隆项目后，requirements.txt 里没有 pandas
# 运行报错：ModuleNotFoundError: No module named 'pandas'
```

✅ **正确写法**：
```python
# 安装包后立即更新 requirements.txt
# 在终端中执行：
# source myenv/bin/activate
# pip install pandas
# pip freeze > requirements.txt

# 验证：cat requirements.txt 能看到 pandas
# 预期输出：requirements.txt 中包含 pandas 及其版本号
```

**为什么错**：requirements.txt 是项目依赖的"清单"，不更新会导致协作时依赖缺失。

---

### 易错点5：使用错误的激活命令

❌ **错误写法**：
```python
# 在 Windows 上使用 Mac 的激活命令
# 在终端中执行：
# source myenv/bin/activate  # Windows 上会报错

# 运行报错：'source' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

✅ **正确写法**：
```python
# 根据操作系统使用正确的命令
# Windows:
# myenv\Scripts\activate

# Mac/Linux:
# source myenv/bin/activate

# 预期输出：命令行提示符前出现 (myenv) 前缀
```

**为什么错**：不同操作系统的激活命令不同，Windows 使用 `.bat` 文件，Mac/Linux 使用 `source` 命令。

## 📝 本课小结

1. **虚拟环境**是每个项目的独立"工具箱"，避免依赖冲突
2. **pip** 是 Python 的包管理器，负责安装、卸载和更新第三方包
3. **requirements.txt** 是项目的依赖清单，方便团队协作和部署
4. **激活虚拟环境**是使用它的前提，不同操作系统命令不同
5. **及时更新 requirements.txt** 是良好工程习惯
