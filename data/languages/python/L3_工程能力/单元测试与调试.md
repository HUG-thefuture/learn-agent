# 📘 L3 工程能力：单元测试与调试

## 🎯 本课目标

学完本课，你将能够：

1. **写出第一个单元测试**：用 `pytest` 和 `unittest` 两种框架，为已有函数编写自动化测试用例。
2. **测试各种场景**：用 `parametrize` 批量测试多组数据，用 `pytest.raises` 断言异常，用 `mock` 模拟外部依赖。
3. **测量并提升代码质量**：用 `coverage` 查看测试覆盖率，用 `pdb` 定位并修复隐藏 bug。

---

## 🧠 概念讲解

### 1. 为什么需要单元测试？

想象你是一个**厨师**，每次炒完一道菜都要自己尝一口。但如果你要炒 100 道菜呢？每道菜都尝一遍太累了，而且可能漏掉某道菜没尝。

**单元测试**就像**自动试菜机器人**——你写一次测试规则，之后每次改动代码，机器人都会自动把所有菜都尝一遍，告诉你哪道菜咸了、哪道菜淡了。

**核心思想**：把函数当成"黑盒子"，输入什么 → 应该输出什么。测试就是验证这个"输入→输出"的对应关系是否正确。

### 2. 两种主流测试框架

| 框架 | 特点 | 适用场景 |
|------|------|----------|
| `unittest` | Python 内置，无需安装 | 项目已有 unittest 代码，或不想装第三方库 |
| `pytest` | 第三方库，语法更简洁 | 新项目推荐，社区主流 |

**为什么推荐 pytest？**
- 写测试**不用继承类**，函数名以 `test_` 开头就行
- 用 Python 原生的 `assert` 断言，不用记 `assertEqual` 等方法名
- 有强大的 `fixture` 和 `parametrize` 功能

### 3. 测试的基本流程

```
写一个函数 → 写测试用例 → 运行测试 → 看结果 → 修复bug → 再运行
```

**测试用例的组成**：
1. **准备**：构造输入数据
2. **执行**：调用被测试的函数
3. **断言**：检查输出是否符合预期

## 💻 完整示例

### 示例 1：用 pytest 测试一个计算器函数

```python
# 这是我们要测试的函数（通常放在单独的文件里，这里为了演示放在一起）
def add(a, b):
    """两数相加"""
    return a + b

def divide(a, b):
    """两数相除，除数为0时抛出异常"""
    if b == 0:
        raise ValueError("除数不能为0")
    return a / b

# ========== 以下是测试代码 ==========
# 测试函数名必须以 test_ 开头
def test_add():
    """测试加法"""
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0

def test_divide():
    """测试除法"""
    assert divide(10, 2) == 5
    assert divide(7, 2) == 3.5

def test_divide_by_zero():
    """测试除数为0时抛出异常"""
    import pytest
    with pytest.raises(ValueError):
        divide(10, 0)

# 运行方式：在终端执行 pytest 文件名.py
# 预期输出：3 passed in 0.01s
```

### 示例 2：用 unittest 测试字符串处理函数

```python
import unittest

def reverse_string(s):
    """反转字符串"""
    return s[::-1]

def count_vowels(s):
    """统计元音字母数量"""
    vowels = "aeiouAEIOU"
    return sum(1 for char in s if char in vowels)

# unittest 需要继承 TestCase 类
class TestStringFunctions(unittest.TestCase):
    
    def test_reverse_string(self):
        """测试字符串反转"""
        self.assertEqual(reverse_string("hello"), "olleh")
        self.assertEqual(reverse_string(""), "")
        self.assertEqual(reverse_string("a"), "a")
    
    def test_count_vowels(self):
        """测试元音统计"""
        self.assertEqual(count_vowels("hello"), 2)  # e, o
        self.assertEqual(count_vowels("AEIOU"), 5)
        self.assertEqual(count_vowels("xyz"), 0)

# 运行方式：在终端执行 python 文件名.py
if __name__ == "__main__":
    unittest.main()

# 预期输出：
# ..
# ----------------------------------------------------------------------
# Ran 2 tests in 0.000s
# OK
```

### 示例 3：用 parametrize 批量测试 + mock 模拟外部依赖

```python
import pytest
from unittest.mock import patch

# 要测试的函数：根据用户ID获取用户信息
def get_user_info(user_id):
    """
    从数据库获取用户信息（这里模拟真实场景）
    实际项目中，这个函数会查询数据库
    """
    # 假设这是数据库查询操作
    database = {
        1: {"name": "Alice", "age": 25},
        2: {"name": "Bob", "age": 30},
    }
    return database.get(user_id)

# 要测试的函数：发送欢迎邮件
def send_welcome_email(user_id):
    """发送欢迎邮件给新用户"""
    user = get_user_info(user_id)
    if not user:
        raise ValueError(f"用户 {user_id} 不存在")
    
    # 这里调用邮件服务（外部依赖）
    email_service = EmailService()
    email_service.send(user["name"], "欢迎加入！")
    return f"邮件已发送给 {user['name']}"

# 模拟外部邮件服务类
class EmailService:
    def send(self, name, message):
        """真实项目中这里会调用SMTP服务器"""
        print(f"发送邮件给 {name}: {message}")

# ========== 测试代码 ==========

# 用 parametrize 批量测试 get_user_info
@pytest.mark.parametrize("user_id, expected_name", [
    (1, "Alice"),
    (2, "Bob"),
])
def test_get_user_info(user_id, expected_name):
    """批量测试不同用户ID"""
    user = get_user_info(user_id)
    assert user["name"] == expected_name

# 测试不存在的用户
def test_get_user_info_not_found():
    """测试不存在的用户返回None"""
    assert get_user_info(999) is None

# 用 mock 模拟 EmailService，避免真的发送邮件
@patch("__main__.EmailService")
def test_send_welcome_email(mock_email_service):
    """测试发送欢迎邮件（不真正发送）"""
    # 设置 mock 的返回值
    mock_email_service.return_value.send.return_value = None
    
    result = send_welcome_email(1)
    assert result == "邮件已发送给 Alice"
    
    # 验证 send 方法被调用了一次
    mock_email_service.return_value.send.assert_called_once()

# 测试用户不存在时抛出异常
def test_send_welcome_email_user_not_found():
    """测试用户不存在时抛出异常"""
    with pytest.raises(ValueError):
        send_welcome_email(999)

# 运行方式：在终端执行 pytest 文件名.py
# 预期输出：5 passed in 0.02s
```

## 📋 常用函数/调用速查表

| 函数/方法 | 签名 | 用途 | 最小示例 |
|-----------|------|------|----------|
| `pytest.raises` | `with pytest.raises(异常类型)` | 断言代码抛出指定异常 | `with pytest.raises(ValueError): divide(1, 0)` |
| `pytest.mark.parametrize` | `@pytest.mark.parametrize("参数名", [值列表])` | 批量参数化测试 | `@pytest.mark.parametrize("a,b", [(1,2),(3,4)])` |
| `@patch` | `@patch("模块.类")` | 替换外部依赖为 mock 对象 | `@patch("__main__.EmailService")` |
| `mock.assert_called_once()` | `mock.方法.assert_called_once()` | 验证方法被调用一次 | `mock.send.assert_called_once()` |
| `unittest.TestCase` | `class TestX(unittest.TestCase)` | unittest 测试类基类 | `class TestAdd(unittest.TestCase)` |
| `assertEqual` | `self.assertEqual(a, b)` | 断言两个值相等 | `self.assertEqual(add(1,2), 3)` |
| `assertRaises` | `self.assertRaises(异常)` | 断言抛出异常 | `self.assertRaises(ValueError, divide, 1, 0)` |
| `breakpoint()` | `breakpoint()` | 设置调试断点 | `breakpoint()` |
| `coverage run` | `coverage run -m pytest` | 运行测试并收集覆盖率 | `coverage run -m pytest test.py` |
| `coverage report` | `coverage report` | 显示覆盖率报告 | `coverage report` |

## ⚠️ 新手易错点

### 易错点1：测试函数名没有以 `test_` 开头

❌ **错误写法**：
```python
# 函数名没有以 test_ 开头，pytest 不会识别为测试
def check_add():
    """这个函数不会被 pytest 执行"""
    assert 1 + 1 == 2

def check_divide():
    """这个也不会被执行"""
    assert 10 / 2 == 5

# 运行 pytest 时，输出：no tests ran
# 预期输出：no tests ran
```

✅ **正确写法**：
```python
# 函数名必须以 test_ 开头
def test_add():
    """测试加法"""
    assert 1 + 1 == 2

def test_divide():
    """测试除法"""
    assert 10 / 2 == 5

# 运行 pytest 时，输出：2 passed
# 预期输出：2 passed in 0.01s
```

**为什么错**：pytest 的默认规则是**只收集**以 `test_` 开头的函数（或以 `_test` 结尾）。函数名不对，测试就不会被执行，你以为测了，其实没测。

### 易错点2：断言写反了（把预期值和实际值搞混）

❌ **错误写法**：
```python
def get_user_name(user_id):
    """根据ID返回用户名"""
    users = {1: "Alice", 2: "Bob"}
    return users.get(user_id)

def test_get_user_name():
    """测试获取用户名"""
    # ❌ 错误：把实际值写在前面，预期值写在后面
    assert "Alice" == get_user_name(1)  # 虽然能运行，但可读性差
    assert "Bob" == get_user_name(2)
    
# 预期输出：2 passed（但可读性差，容易混淆）
```

✅ **正确写法**：
```python
def get_user_name(user_id):
    """根据ID返回用户名"""
    users = {1: "Alice", 2: "Bob"}
    return users.get(user_id)

def test_get_user_name():
    """测试获取用户名"""
    # ✅ 正确：实际值在前，预期值在后
    assert get_user_name(1) == "Alice"
    assert get_user_name(2) == "Bob"
    
# 预期输出：2 passed in 0.01s
```

**为什么错**：虽然两种写法都能运行，但 `assert 实际值 == 预期值` 的写法更符合直觉。当断言失败时，错误信息会显示"实际值"和"预期值"，顺序正确更容易快速定位问题。

### 易错点3：测试代码和被测试代码混在一起

❌ **错误写法**：
```python
# 把测试代码写在业务代码文件里
def calculate_discount(price, discount_rate):
    """计算折扣后价格"""
    if discount_rate < 0 or discount_rate > 1:
        raise ValueError("折扣率必须在0到1之间")
    return price * (1 - discount_rate)

# ❌ 测试代码混在业务代码里
def test_calculate_discount():
    assert calculate_discount(100, 0.2) == 80
    assert calculate_discount(100, 0) == 100

# 直接运行这个文件，测试不会自动执行
# 预期输出：无输出（测试没有运行）
```

✅ **正确写法**：
```python
# 业务代码文件：discount.py
def calculate_discount(price, discount_rate):
    """计算折扣后价格"""
    if discount_rate < 0 or discount_rate > 1:
        raise ValueError("折扣率必须在0到1之间")
    return price * (1 - discount_rate)

# ========== 测试代码文件：test_discount.py ==========
# 单独的文件，文件名以 test_ 开头
from discount import calculate_discount

def test_calculate_discount():
    """测试折扣计算"""
    assert calculate_discount(100, 0.2) == 80
    assert calculate_discount(100, 0) == 100
    assert calculate_discount(100, 1) == 0

# 在终端运行：pytest test_discount.py
# 预期输出：1 passed in 0.01s
```

**为什么错**：测试代码应该**独立成文件**（通常以 `test_` 开头），这样：
1. 业务代码更干净，不包含测试逻辑
2. 可以单独运行测试，不影响业务代码
3. 方便用 `coverage` 等工具分析覆盖率

### 易错点4：用 `print` 调试而不是用 `pdb` 断点

❌ **错误写法**：
```python
def process_data(data_list):
    """处理数据列表"""
    result = []
    for i, item in enumerate(data_list):
        # ❌ 用 print 调试，改完还要删掉
        print(f"处理第{i}个元素: {item}")
        if item % 2 == 0:
            result.append(item * 2)
        else:
            result.append(item + 1)
    return result

# 运行后输出一堆调试信息，但无法交互式检查变量
data = [1, 2, 3, 4, 5]
print(process_data(data))
# 预期输出：处理第0个元素: 1 ...（一堆print，无法交互）
```

✅ **正确写法**：
```python
def process_data(data_list):
    """处理数据列表"""
    result = []
    for i, item in enumerate(data_list):
        # ✅ 用 breakpoint() 设置断点，可以交互式检查
        breakpoint()  # 程序运行到这里会暂停，进入 pdb 调试模式
        if item % 2 == 0:
            result.append(item * 2)
        else:
            result.append(item + 1)
    return result

# 运行后会在 breakpoint() 处暂停，可以输入 p item 查看变量值
data = [1, 2, 3, 4, 5]
print(process_data(data))
# 预期输出：进入 pdb 调试模式，输入 c 继续执行
```

**为什么错**：`print` 调试需要手动添加和删除，而且无法交互式查看变量。`breakpoint()` 会进入 pdb 调试器，你可以：
- 输入 `p 变量名` 查看变量值
- 输入 `n` 执行下一行
- 输入 `c` 继续运行直到下一个断点
- 输入 `q` 退出调试

### 易错点5：测试用例之间互相依赖

❌ **错误写法**：
```python
# 全局变量被多个测试共享
user_database = {}

def add_user(name):
    """添加用户"""
    user_id = len(user_database) + 1
    user_database[user_id] = name
    return user_id

def test_add_first_user():
    """测试添加第一个用户"""
    user_id = add_user("Alice")
    assert user_id == 1
    assert user_database[user_id] == "Alice"

def test_add_second_user():
    """测试添加第二个用户"""
    # ❌ 依赖第一个测试已经执行过
    user_id = add_user("Bob")
    assert user_id == 2  # 如果只运行这个测试，user_id 会是 1
    assert user_database[user_id] == "Bob"

# 单独运行 test_add_second_user 会失败
# 预期输出：单独运行第二个测试时失败（因为 user_database 是空的）
```

✅ **正确写法**：
```python
# 使用 fixture 为每个测试提供独立的数据
import pytest

@pytest.fixture
def user_database():
    """每个测试都会获得一个新的空字典"""
    return {}

def add_user(db, name):
    """添加用户"""
    user_id = len(db) + 1
    db[user_id] = name
    return user_id

def test_add_first_user(user_database):
    """测试添加第一个用户"""
    user_id = add_user(user_database, "Alice")
    assert user_id == 1
    assert user_database[user_id] == "Alice"

def test_add_second_user(user_database):
    """测试添加第二个用户"""
    # ✅ 每个测试都有独立的 user_database
    user_id = add_user(user_database, "Bob")
    assert user_id == 1  # 因为每个测试都是新的空字典
    assert user_database[user_id] == "Bob"

# 单独运行任何一个测试都能通过
# 预期输出：2 passed in 0.01s
```

**为什么错**：测试应该**相互独立**。如果测试 A 依赖测试 B 先执行，那么：
1. 单独运行测试 A 会失败
2. 测试顺序改变会导致结果不同
3. 难以定位是哪个测试出了问题

```python
import requests
from unittest.mock import patch

def get_weather(city):
    """获取城市天气（真实项目中会调用天气API）"""
    response = requests.get(f"https://api.weather.com/{city}")
    return response.json()["temperature"]

@patch("__main__.requests.get")
def test_get_weather(mock_get):
    """测试获取天气"""
    # 模拟 API 返回的数据
    mock_get.return_value.json.return_value = {"temperature": 25}
    
    # 调用函数并断言结果
    assert get_weather("北京") == 25
    
    # 验证 requests.get 被调用了一次
    mock_get.assert_called_once_with("https://api.weather.com/北京")
```

## 📝 本课小结

1. **单元测试是代码的"安全网"**：每次改动代码后运行测试，能快速发现是否破坏了原有功能。
2. **pytest 比 unittest 更简洁**：函数名 `test_` 开头 + 原生 `assert`，学习成本更低。
3. **parametrize 批量测试**：用一组数据测同一个函数，减少重复代码。
4. **mock 模拟外部依赖**：测试时不真正访问网络/数据库，让测试更快更稳定。
5. **覆盖率工具**：用 `coverage` 查看哪些代码没被测试到，针对性补充测试。

**下一课建议**：学习「代码重构与设计模式」，让你的代码更易测试、更易维护。
