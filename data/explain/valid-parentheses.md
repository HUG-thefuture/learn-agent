# 20. 有效的括号 —— 题解讲解

## 一、思路推导

### 1. 从定义出发

"有效"的字符串满足一个递归文法：

```
Valid := ε                    （空串）
       | Valid Valid          （拼接）
       | ( Valid ) | [ Valid ] | { Valid }   （嵌套）
```

这个文法天然具有**嵌套结构**。嵌套结构的核心性质是：**最后打开的括号，必须最先被闭合**——这正是后进先出（LIFO）的语义，直接指向**栈**。

### 2. 用例子验证直觉

**有效例子 `{[()]}`：**

| 字符 | 动作 | 栈（右端为栈顶） |
|------|------|------|
| `{` | 入栈 | `{` |
| `[` | 入栈 | `{ [` |
| `(` | 入栈 | `{ [ (` |
| `)` | 栈顶 `(` 匹配，弹出 | `{ [` |
| `]` | 栈顶 `[` 匹配，弹出 | `{` |
| `}` | 栈顶 `{` 匹配，弹出 | 空 ✅ |

**无效例子 `([)]`：** 遇到 `)` 时栈顶是 `[`，类型不匹配 → 无效。

### 3. 为什么"计数器"不行？

`([)]` 中三种括号的数量各自配平（1 对圆、1 对方），但顺序错误。计数器只能记录"数量"，无法记录"嵌套顺序"，所以必须用栈保存**未闭合左括号的序列**。

### 4. 归纳算法

从左到右扫描：
- 遇到**左括号** → 入栈（等待未来匹配）；
- 遇到**右括号** → 栈顶必须是对应的左括号，匹配则弹出，否则立即返回 `False`；
- 扫描结束后，**栈必须为空**（否则有左括号未闭合）。

**边界情况清单：**

| 输入 | 结果 | 原因 |
|------|------|------|
| `""` | `True` | 空串有效 |
| `"("` / `"((("` | `False` | 结束时栈非空 |
| `")"` / `")))"` | `False` | 右括号到来时栈为空 |
| `"([)]"` | `False` | 栈顶类型不匹配 |
| 长度为奇数 | `False` | 必然有落单的括号，可提前剪枝 |

## 二、推荐解法：栈（Python）

```python
class Solution:
    def isValid(self, s: str) -> bool:
        # 剪枝：奇数长度必然无效
        if len(s) % 2 == 1:
            return False

        pairs = {')': '(', ']': '[', '}': '{'}  # 右括号 -> 对应左括号
        stack = []

        for ch in s:
            if ch in pairs:                     # 右括号：检查栈顶
                if not stack or stack.pop() != pairs[ch]:
                    return False
            else:                               # 左括号：入栈
                stack.append(ch)

        return not stack                        # 栈空才说明全部闭合
```

### 实现要点与易错点

1. **`if not stack or stack.pop() != ...` 的短路求值**：先判空再弹出，避免对空栈 `pop()` 抛 `IndexError`。这是本题最常见的 bug。
2. **最后必须 `return not stack`** 而不是 `return True`：否则 `"((("` 会被误判为有效。
3. **用"右括号 → 左括号"的映射**：只需一个字典，遇到右括号时查表即可；若反过来映射，遇到左括号时无法区分三种右括号该弹谁（其实可以，但查表方向这样更顺）。
4. **Python 的 `list` 作栈**：`append` / `pop()`（末尾）均为均摊 O(1)，无内存泄漏问题，函数返回后自动回收。
   - Java 侧建议用 `ArrayDeque<Character>`，避免遗留的 `java.util.Stack`（继承 `Vector`，带同步锁，官方已不推荐）。
   - JS 侧 `array.push/pop` 即可。
5. **可测试性**：核心逻辑是纯函数，适合直接写断言测试：

```python
def test_is_valid():
    f = Solution().isValid
    assert f("") is True
    assert f("()") is True
    assert f("()[]{}") is True
    assert f("{[()]}") is True
    assert f("(]") is False
    assert f("([)]") is False
    assert f("(((") is False
    assert f(")") is False
    assert f("(") is False
```

## 三、复杂度分析

- **时间复杂度：O(n)**。每个字符只被处理一次；字典查找、入栈、出栈均为 O(1)。最坏情况下在中间某个右括号处提前返回，实际还会更快。
- **空间复杂度：O(n)**。最坏情况是全部为左括号（如 `"((((("`），栈中压入 n 个元素。剪枝（奇数长度）不影响渐进复杂度，但能省一半无效扫描。

## 四、其他解法对比

### 解法 A：反复替换（暴力）

不断把成对的 `()`/`[]`/`{}` 替换为空串，直到无法替换，最后判断是否为空：

```python
def isValid(s: str) -> bool:
    while '()' in s or '[]' in s or '{}' in s:
        s = s.replace('()', '').replace('[]', '').replace('{}', '')
    return s == ''
```

- 思路直观，但每次 `replace` 生成新字符串 O(n)，最多替换 O(n) 轮 → **O(n²) 时间**，对 `"((((...))))"` 这类深嵌套输入会超时。仅适合小规模或作为引出栈的铺垫。

### 解法 B：栈的变体——压入"期望的右括号"

遇到左括号时，直接把**它对应的右括号**压栈；遇到右括号时只需比较是否相等：

```python
def isValid(s: str) -> bool:
    if len(s) % 2:
        return False
    match = {'(': ')', '[': ']', '{': '}'}
    stack = []
    for ch in s:
        if ch in match:
            stack.append(match[ch])
        elif not stack or stack.pop() != ch:
            return False
    return not stack
```

- 匹配逻辑更简洁（省去查表比较），本质与推荐解法等价，同为 O(n)/O(n)。个人偏好问题。

### 解法 C：计数器

只适用于**单一括号类型**（如只有 `()`）：左括号 `+1`，右括号 `-1`，中途为负或结尾非零即无效。**多类型下失效**——无法检测 `([)]` 的交错顺序。它的价值在于引出"计数器是栈的退化形式（只存数量、不存顺序）"这一理解。

### 对比总结

| 解法 | 时间 | 空间 | 正确性 | 评价 |
|------|------|------|--------|------|
| 栈（推荐） | O(n) | O(n) | ✅ | 标准解，面试首选 |
| 压期望右括号 | O(n) | O(n) | ✅ | 等价变体，代码更短 |
| 反复替换 | O(n²) | O(n) | ✅ | 简单但低效，勿用于大数据 |
| 计数器 | O(n) | O(1) | ❌ 多类型 | 只适用单括号类型 |

本题是**"栈处理匹配/嵌套"**这一模式的原型，掌握后可平移到大量题目：

| 921. 使括号有效的最少添加 | 单类型，计数器即可 |
| 1249. 移除无效的括号 | 栈标记待删除下标 |
| 1541. 平衡括号字符串的最少插入 | 计数 + 修复策略 |

| 150. 逆波兰表达式求值 | 栈匹配运算数 |
| 394. 字符串解码 | 栈保存上下文（倍数 + 前缀） |
| 71. 简化路径 | 栈处理路径层级 |

**模式总结**：只要问题中出现"最近出现的 X 要最先被处理/抵消/匹配"（括号、标签、路径回退、表达式求值、撤销操作），就优先考虑栈。本题的三个检查点——**弹空前判空、弹出不匹配即失败、结束后栈必须为空**——是所有栈匹配类题目的通用模板，务必形成肌肉记忆。
