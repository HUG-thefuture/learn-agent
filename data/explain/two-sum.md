# 力扣 1. 两数之和 题解

## 1) 思路推导

**题目要求**：在数组中找两个不同下标的数，使 `nums[i] + nums[j] == target`，返回 `[i, j]`。

**从暴力到优化的推导过程**：

- **最直觉的做法**：枚举所有数对 `(i, j)`，判断和是否为 target。这是 O(n²)。
- **观察瓶颈**：暴力中，对每个 `nums[i]`，我们其实是在问——"数组里有没有 `target - nums[i]` 这个数？"这个"查找"操作花了 O(n)。
- **优化方向**：把"查找"从 O(n) 降到 O(1)。**哈希表**正好擅长这个：用空间换时间，把见过的数存进字典，键为数值、值为下标。
- **关键细节（边遍历边查，而非先建全表）**：
  - 遍历到 `nums[i]` 时，先查 `target - nums[i]` 是否已在表中，再把自己存入。
  - **先查后存**保证不会用到同一个元素两次（如 `nums=[3,2,4], target=6`，不能返回 `[0,0]`）。
  - 同时天然处理重复值：`nums=[3,3], target=6`，第二个 `3` 查表时能命中第一个 `3` 的下标。

## 2) 推荐解法与代码（一次遍历哈希表）

```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}  # 数值 -> 下标
        for i, x in enumerate(nums):
            complement = target - x
            if complement in seen:          # 先查：之前的某个数与当前数配对
                return [seen[complement], i]
            seen[x] = i                     # 后存：保证不会匹配到自己
        return []  # 题目保证恰有一解，此分支仅为健壮性
```

**边界与正确性说明**：
- 重复元素（`[3,3]`）：先查后存，正确返回 `[0,1]`。
- 负数、零：哈希表对值无假设，均适用。
- 若题目不保证有解，返回 `[]` 或抛异常即可，函数行为明确。

## 3) 复杂度分析

| 指标 | 结果 | 说明 |
|---|---|---|
| 时间 | **O(n)** | 每个元素只做一次哈希查找 + 一次插入，均为均摊 O(1) |
| 空间 | **O(n)** | 最坏情况下哈希表存 n−1 个元素 |

## 4) 其他解法对比

| 解法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 暴力双循环 | O(n²) | O(1) | 简单直接，n 小时可用；面试中应作为引出优化的起点 |
| 排序 + 双指针 | O(n log n) | O(n) | 排序会打乱下标，需额外存 `(值, 原下标)` 再排序；适合**数组已有序**的场景（如 167 题） |
| **哈希表（推荐）** | O(n) | O(n) | 一次遍历，不破坏下标，通用性最好 |

**排序 + 双指针参考**（了解即可）：

```python
def twoSum_sorted(nums, target):
    pairs = sorted((x, i) for i, x in enumerate(nums))
    lo, hi = 0, len(pairs) - 1
    while lo < hi:
        s = pairs[lo][0] + pairs[hi][0]
        if s == target:
            return [pairs[lo][1], pairs[hi][1]]
        if s < target:
            lo += 1
        else:
            hi -= 1
```

**选型结论**：无序数组 → 哈希表；已排序/要求 O(1) 空间 → 双指针。

## 5) 同类题拓展

本题的核心套路是 **"补数查找"（complement lookup）**，可迁移到一系列题：

| 题目 | 变化点 | 套路 |
|---|---|---|
| 167. 两数之和 II（有序数组） | 输入已排序 | 双指针 O(n)/O(1)，无需哈希 |
| 170. 两数之和 III（设计类） | 流式 add/find | add 存计数表，find 查补数（注意处理重复） |
| 15. 三数之和 | 找三元组且**去重** | 排序 + 固定一个数 + 双指针，重点在去重技巧 |
| 18. 四数之和 | 四元组 | 三数之和再套一层循环，注意剪枝防超时 |
| 454. 四数相加 II | 四个独立数组 | 分组：A+B 的所有和存哈希表，查 `-(C+D)`，O(n²) |
| 560. 和为 K 的子数组 | 子数组（连续） | 前缀和 + 哈希表：查 `prefix - k` 是否出现过 |
| 1679. K 和数对的最大数目 | 每个数只能用一次，求对数 | 哈希计数，配对后计数减一 |

**一句话总结**：看到"两数之和/差/积满足某条件"，先想"遍历时能否用哈希表 O(1) 查到所需的另一半"；数组有序则优先考虑双指针。
