# 13. 罗马数字转整数

## 1) 思路推导

**先看规则本质**。罗马数字用 7 个符号表示数值：

```
I=1  V=5  X=10  L=50  C=100  D=500  M=1000
```

它的构造是"**贪心 + 从大到小排布**"，但为了避免 `IIII` 这类写法，引入了 6 种**减法组合**：

```
IV=4  IX=9  XL=40  XC=90  CD=400  CM=900
```

**关键观察**：这 6 种组合有一个共同特征——**左小右大**。

于是整个解法可以归约成一个很轻的判据：

> 从左到右扫描，若当前字符的值 **小于** 右边字符的值，说明当前字符是减法组合的左半部分，应**减**；否则**加**。

拿 `MCMXCIV` 手动跑一遍验证：

| i | 字符 | 值 | 右侧值 | 大小关系 | 操作 |
|---|------|----|--------|----------|------|
| 0 | M | 1000 | 100 | 大 | +1000 |
| 1 | C | 100 | 1000 | 小 | −100 |
| 2 | M | 1000 | 10 | 大 | +1000 |
| 3 | X | 10 | 100 | 小 | −10 |
| 4 | C | 100 | 1 | 大 | +100 |
| 5 | I | 1 | 5 | 小 | −1 |
| 6 | V | 5 | — | 末尾 | +5 |

合计 `1000−100+1000−10+100−1+5 = 1994` ✓

**为什么"只看相邻一位"就够了？** 因为题目保证输入是合法罗马数字。合法的减法组合只有那 6 种，且被减数（I/X/C）只出现一次、紧贴其右邻的减数。所以"左小右大"这个局部特征与"属于减法组合"是**一一对应**的，无需回溯或额外状态。

## 2) 推荐解法与代码（Python）

### 解法一：从左到右，比较相邻字符（首选）

```python
class Solution:
    def romanToInt(self, s: str) -> int:
        val = {'I': 1, 'V': 5, 'X': 10, 'L': 50,
               'C': 100, 'D': 500, 'M': 1000}

        total, n = 0, len(s)
        for i, ch in enumerate(s):
            v = val[ch]
            # 右邻居存在且比当前大 -> 减法组合的左半部分
            if i + 1 < n and v < val[s[i + 1]]:
                total -= v
            else:
                total += v
        return total
```

**易错点**：`i + 1 < n` 这个边界判断。Python 里漏掉它会在最后一个字符处抛 `IndexError`（若用别的语言则是越界读）。

### 解法二：从右向左，维护"已见最大值"

换个视角：从右往左扫，维护右侧出现过的最大字符值 `prev`。当前值 `< prev` 就减，否则加并更新 `prev`。这个写法**完全不需要下标和边界判断**，在 C/Java 里更不容易写错，也天然契合"从低位往高位读"的直觉。

```python
class Solution:
    def romanToInt(self, s: str) -> int:
        val = {'I': 1, 'V': 5, 'X': 10, 'L': 50,
               'C': 100, 'D': 500, 'M': 1000}

        total, prev = 0, 0
        for ch in reversed(s):
            v = val[ch]
            if v < prev:          # 比右侧最大值小 -> 减法
                total -= v
            else:
                total += v
                prev = v
        return total
```

两种写法我都建议掌握：解法一更贴近题意描述（"看右边"），解法二更工程化（无边界风险）。

## 3) 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | **O(n)** | 每个字符恰好访问一次，字典查询 O(1) |
| 空间 | **O(1)** | 字典固定 7 项；`reversed` 是迭代器不复制字符串。仅常数个临时变量 |

n ≤ 15（题目范围 1≤num≤3999，字符串最长 15），所以实际上任何常数级开销都可忽略，但**面试中必须说出 O(n) / O(1)**，这是考点。

> 严格说解法一的 `s[i+1]` 是 O(1) 随机访问（Python 字符串按码点索引，对 ASCII 是 O(1)），不引入额外复杂度。

## 4) 其他解法对比

### 方案 A：双字符优先匹配（贪心）

一次尝试匹配 2 个字符，命中减法组合就 +2 步，否则匹配 1 个字符 +1 步。

```python
class Solution:
    def romanToInt(self, s: str) -> int:
        table = {'I': 1, 'V': 5, 'X': 10, 'L': 50, 'C': 100, 'D': 500, 'M': 1000,
                 'IV': 4, 'IX': 9, 'XL': 40, 'XC': 90, 'CD': 400, 'CM': 900}
        total, i, n = 0, 0, len(s)
        while i < n:
            if i + 1 < n and s[i:i + 2] in table:   # 二维优先
                total += table[s[i:i + 2]]
                i += 2
            else:
                total += table[s[i]]
                i += 1
        return total
```

- **优点**：把 6 种减法组合显式列出，语义最直白；无需理解"相邻比较"的技巧。
- **缺点**：代码更长；每次 `s[i:i+2]` 会创建临时字符串（虽然是 O(1)）；`in` 判断多一次哈希。思想上等价于"最长匹配优先"，靠合法输入保证正确性。

### 方案 B：字符串替换法（面试可提，别当主解法）

把减法组合先展开成同值的一段相同字符，再逐字符累加：

```python
class Solution:
    def romanToInt(self, s: str) -> int:
        # 先处理双字符组合，再逐字符求和
        for pair, expand in [('CM', 'DCCCC'), ('CD', 'CCCC'),
                             ('XC', 'LXXXX'), ('XL', 'XXXX'),
                             ('IX', 'VIIII'), ('IV', 'IIII')]:
            s = s.replace(pair, expand)
        val = {'I': 1, 'V': 5, 'X': 10, 'L': 50,
               'C': 100, 'D': 500, 'M': 1000}
        return sum(val[ch] for ch in s)
```

- **优点**：思路极其形象，适合口头讲解"减法组合是什么"。
- **缺点**：**不可作为推荐解**。① 每次 `s.replace` 都新建字符串，字符串长度最多膨胀到约 4 倍，时间 O(n·k)（k 为替换轮数 6），常数远大于前两者；② 依赖替换顺序的隐式正确性（本题中 6 个模式两两不重叠，顺序恰好任意，但读者容易误以为无关；更稳妥的做法是按数值从大到小替换）；③ 是"先破坏输入结构再求和"，可读性上反而不如直接判正负。

### 方案 C：预先建表 + 一次性查两字符（性能向）

把 `'IV'` 这类两字符组合编码成一个整数 key（如 `ord(a)*128 + ord(b)`）放进数组做 O(1) 查表。对 n≤15 完全没必要，属于过度优化，仅在超大规模解析器场景有意义。

### 汇总对比

| 解法 | 时间 | 空间 | 代码量 | 推荐度 |
|------|------|------|--------|--------|
| 从左到右比较相邻（解法一） | O(n) | O(1) | 短 | ★★★★★ |
| 从右到左维护 prev（解法二） | O(n) | O(1) | 短，无边界风险 | ★★★★★ |
| 双字符优先匹配 | O(n) | O(1) | 中 | ★★★★ |
| 字符串替换 | O(n·k) | O(n) | 短 | ★★（仅讲解用） |

## 5) 同类题拓展

**镜像题 / 逆过程**
- **12. 整数转罗马数字**：本题的逆运算。用**贪心**从大到小（`1000,900,500,400,...`）搭配硬编码表即可，与本题合起来是一套完整训练。
- **273. 整数转换英文表示**：同属"数字 → 符号系统"，三位一组 + 贪心，难点在边界（零、空格、`-`）。

**同类型"符号/表达式解析"**
- **8. 字符串转换整数 (atoi)**：状态机 + 溢出裁剪，考察边界。
- **171. Excel 表列序号**：`A→1, ..., Z→26` 的**进制换算**，是"逐位加权求和"的对应题型；逆题为 **168. Excel 表列名称**（需要先做 `-1` 偏移，坑在整除边界）。
- **394. 字符串解码**：栈 + 嵌套解析。
- **150. 逆波兰表达式求值**：栈式表达式求值，可与"相邻比较"做对照。
- **640. 求解方程**：解析一元一次方程，考的是 token 切分与符号处理。

**思想延伸**
- **相邻比较决定正负**这个技巧，在**山脉数组 / 股票涨跌 / 单调性判断**类题中反复出现（如 896. 单调数列、121. 买卖股票）。
- **贪心 + 硬编码表**的模式，在 12 题、322. 零钱兑换（对比贪心的失效）中形成正反两面参考。

**一句话总结**：本题是"**局部特征归约全局语义**"的经典案例——只要证明"左小右大 ⇔ 减法组合"，O(n)/O(1) 的实现就是水到渠成。
