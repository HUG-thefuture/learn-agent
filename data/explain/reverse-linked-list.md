# 206. 反转链表 题解

## 1. 思路推导

**题目**：给定单链表头结点 `head`，反转整个链表，返回新的头结点。

链表节点定义：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

### 核心观察

单链表只能"顺着 next 往前走"，无法回头。要反转，就必须**把每个节点的 `next` 指针从"指向后一个"改成"指向前一个"**。

但一旦修改 `cur.next`，原本的"后一个节点"就丢了。所以必须**在改指针之前，先把下一个节点存起来**。

### 需要几个指针？

- `prev`：当前节点的前驱（反转后 `cur.next` 要指向它）
- `cur`：当前正在处理的节点
- `nxt`：当前节点的后继（改指针前先保存，防止断链）

### 迭代过程（以 1→2→3→None 为例）

| 步骤 | prev | cur | nxt | 操作 |
|------|------|-----|-----|------|
| 初始 | None | 1 | — | — |
| 1 | None | 1 | 2 | `1.next = None`，prev=1，cur=2 |
| 2 | 1 | 2 | 3 | `2.next = 1`，prev=2，cur=3 |
| 3 | 2 | 3 | None | `3.next = 2`，prev=3，cur=None |
| 结束 | 3 | None | — | 返回 prev=3 |

**关键顺序**（不能颠倒）：

```python
nxt = cur.next      # ① 先保存后继
cur.next = prev     # ② 再反转指针
prev = cur          # ③ prev 前移
cur = nxt           # ④ cur 前移
```

如果先执行 `cur.next = prev` 再取 `cur.next`，就会拿到已经改掉的值，导致断链。

### 边界情况

- `head is None`：空链表，直接返回 `None`
- 只有一个节点：循环一次，`cur.next = None`，返回该节点，正确逆向
- 循环终止条件：`cur is None`（走完了），此时 `prev` 恰好是原链表尾 = 新头

## 2. 推荐解法与代码（Python）

**迭代法（三指针）**：最直观、O(1) 空间、无递归栈风险，面试首选。

```python
class Solution:
    def reverseList(self, head: ListNode) -> ListNode:
        prev = None          # 新链表的"前一个"节点，初始为空
        cur = head           # 当前待处理节点

        while cur:
            nxt = cur.next   # ① 先保存后继，防止断链
            cur.next = prev  # ② 反转：当前节点指向前驱
            prev = cur       # ③ prev 前移
            cur = nxt        # ④ cur 前移（用保存好的 nxt）

        return prev          # 循环结束时 cur 为 None，prev 即新头结点 Freeman
```

**递归法**（同样推荐掌握，代码更短）：

```python
class Solution:
    def reverseList(self, head: ListNode) -> ListNode:
        # 递归终止：空链表或只剩一个节点，它就是新头
        if head is None or head.next is None:
            return head

        # 先反转后面的部分，new_head 是整条新链表的头（原链表尾）
        new_head = self.reverseList(head.next)

        # 此时 head.next 是反转后子链表的尾，让它指回 head
        head.next.next = head
        # head 变成新尾，必须断开原来的 next，否则成环
        head.next = None

        return new_head
```

> 递归写法最容易错的是**忘记 `head.next = None`**，会导致尾节点成环、无限循环。

## 3. 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 迭代 | O(n) | **O(1)** | 每个节点访问一次，只用 3 个指针 |
| 递归 | O(n) | O(n) | 递归栈深度 = 链表长度，n 很大时可能栈溢出 |

- **时间**：两种都是每个节点恰好处理一次，n 为节点数。
- **空间**：迭代是常数级，是本题的最优空间解；递归的 O(n) 来自调用栈，不是显式分配。

## 4. 其他解法对比

### ① 头插法（新建哑结点，逐个摘下头插）

```python
def reverseList(self, head):
    dummy = ListNode(0)
    while head:
        nxt = head.next
        head.next = dummy.next   # 插到 dummy 后面
        dummy.next = head
        head = nxt
    return dummy.next
```

- 思路：把原链表节点一个个"摘下来"，头插到新链表。
- 优点：直观，适合不熟悉三指针的人；**缺点**：多一个哑结点，本质和迭代法一样，但常数稍大。
- 复杂度：O(n) / O(1)。

### ② 递归法

- 优点：代码短，体现"分治"思想（先反转 `head.next` 之后的部分，再处理当前节点）。
- 缺点：空间 O(n)，链表很长（如 10^5）时可能 **RecursionError**；逻辑绕，容易漏 `head.next = None`。
- 适用：面试时作为"第二种思路"补充，展示对递归的理解。

### ③ 栈 / 数组辅助

- 把节点依次压栈，再弹出重新连 `next`。
- 复杂度：O(n) / O(n)，**不推荐**——纯属为了反转而浪费空间，迭代法已是最优。

### ④ 就地"三指针"迭代（本文推荐）

- 时间 O(n)、空间 O(1)，无递归风险，是**标准最优解**。

**结论**：生产/面试首选迭代三指针；递归作为思路拓展；栈和数组仅用于理解，不推荐。

### 一句话总结

反转链表的本质是**"改指针方向"**，难点在于**改之前先保存后继**；迭代三指针 `prev / cur / nxt` 是 O(n) 时间、O(1) 空间的最优解，递归版优雅但有栈风险，务必记得 `head.next = None` 断环。
