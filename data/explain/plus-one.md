# LeetCode 66. 加一（Plus One）题解

## 1. 思路推导

### 1.1 题目本质

数组 `digits` 是某个非负整数的十进制表示，**高位在前**（`digits[0]` 是最高位），每个元素是一位数字。要做的是「+1」。

加法的核心是**进位传播**。但对于「+1」这个特例，有一个非常好的性质：

> 进位只可能从末位开始，且一旦某一位加 1 后不需要进位，后面的高位就完全不受影响，可以直接结束。

因此不需要像通用大数加法那样维护 `carry` 变量——因为 carry 至多传播到第一个「不等于 9」的位就停止了。

### 1.2 分类讨论

从末位往前看，只有两种情况：

| 情况 | 例子 | 处理 |
|---|---|---|
| 末位 `< 9` | `[1,2,3]` | 末位 +1 直接返回 → `[1,2,4]` |
| 末位 `== 9` | `[1,2,9]` | 末位置 0，向左继续看 |
| 连续 9 但未到最高位 | `[1,9,9]` | 两个 9 都置 0，`1` 变 `2` → `[2,0,0]` |
| 全是 9 | `[9,9,9]` | 全部置 0，**长度 +1**，首位补 1 → `[1,0,0,0]` |

关键观察：**「全是 9」是唯一会导致数组变长的情况**，此时结果一定是 `[1, 0, 0, ..., 0]`，长度 `n + 1`。

### 1.3 算法步骤

1. 从 `i = n - 1` 往 `0` 逆序遍历；
2. 若 `digits[i] < 9`：`digits[i] += 1`，**立即返回**；
3. 否则 `digits[i] = 9`，置为 `0`，继续向左；
4. 若循环结束仍未返回，说明原数组全是 9，返回 `[1] + digits`。

由于是「高位在前」，逆序遍历恰好对应「从低位到高位」，这正是进位传播的方向。

## 2. 推荐解法（Python）

```python
from typing import List


class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        # 从最低位（数组末尾）开始模拟进位
        for i in range(len(digits) - 1, -1, -1):
            if digits[i] < 9:
                # 不需要进位，加一后直接结束
                # 这一点之后的所有高位都不会变化
                digits[i] += 1
                return digits
            # 当前位是 9，加一后变成 0，进位继续向左传播
            digits[i] = 0

        # 走到这里说明原数组全是 9（如 [9,9,9]）
        # 结果长度 +1，形如 [1, 0, 0, 0]
        # 注意：此时 digits 已被原地改成全 0，这里返回的是新列表
        return [1] + digits
```

### 测试代码

```python
if __name__ == "__main__":
    s = Solution()
    cases = [
        ([1, 2, 3], [1, 2, 4]),          # 末位不进位
        ([4, 3, 2, 1], [4, 3, 2, 2]),
        ([1, 2, 9], [1, 3, 0]),          # 部分进位
        ([1, 9, 9], [2, 0, 0]),
        ([9], [1, 0]),                   # 单位数 9
        ([9, 9, 9], [1, 0, 0, 0]),       # 全 9，长度扩张
        ([0], [1]),                      # 唯一的「有前导零」特例
        ([8, 9, 9, 9], [9, 0, 0, 0]),
    ]
    for inp, expected in cases:
        got = s.plusOne(inp[:])          # 传副本，避免用例被原地修改污染
        assert got == expected, f"{inp} -> {got}, expected {expected}"
    print("all tests passed")
```

> 小提示：`plusOne` 会**原地修改**入参 `digits`。如果调用方后续还要使用原数组，需要先 `digits[:]` 拷贝一份——这也是上面测试代码传副本的原因。

## 3. 复杂度分析

| 维度 | 复杂度 | 说明 |
|---|---|---|
| 时间 | 最坏 `O(n)`，最好 `O(1)` | 只有末尾连续 9 的个数决定循环次数；全 9 时才遍历整个数组 |
| 空间 | `O(1)` 额外空间 | 只用了循环变量 `i`，原地修改 |
| 返回值 | 最坏 `O(n)` | 全 9 时 `[1] + digits` 会新建长度 `n+1` 的列表 |

补充两点直觉：

- **平均时间复杂度接近 `O(1)`**：末位不是 9 的概率是 9/10，连续 `k` 个 9 的概率是 `(1/10)^k`，期望进位长度是常数级（约 1/9）。
- **关于「内存泄漏」**：Python 有 GC，本题也不涉及文件/连接等资源。唯一值得注意的实践是**不要为了「安全」而无谓地拷贝数组**——在 LeetCode 允许原地修改时，原地解法就是最省内存的。

## 4. 其他解法对比

### 4.1 解法 A：转成整数再 +1（不推荐用于面试）

```python
class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        num = int(''.join(map(str, digits))) + 1
        return [int(c) for c in str(num)]
```

- **优点**：一行思路，直观。
- **缺点**：
  - 典型语言陷阱。C++/Java 的 `long long` 最多 19 位就溢出，而题目数组长度可到 100，**必然溢出**；只有 Python 因原生大整数才安全。
  - Python 3.11+ 默认限制 `int` 与字符串互转的位数（`sys.set_int_max_str_digits`，默认 4300 位），超长输入会直接抛 `ValueError`。
  - 额外 `O(n)` 字符串空间，常数大。
- **结论**：面试中写这个会被追问「如果数组有 100 位呢？」——它恰恰**丢掉了本题想考察的进位思想**。

### 4.2 解法 B：显式 carry 的大数加法模板

```python
class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        carry, i = 1, len(digits) - 1
        while carry and i >= 0:
            s = digits[i] + carry
            digits[i] = s % 10
            carry = s // 10
            i -= 1
        if carry:
            digits.insert(0, 1)   # O(n)
        return digits
```

- **优点**：通用模板，稍作修改就能解「加任意数」「两数相加」「字符串相加」。
- **缺点**：对「+1」来说略冗长；`insert(0, 1)` 是 `O(n)` 搬移（用 `[1] + digits` 语义更清晰）。

### 4.3 解法 C：找最后一个非 9 的位置

```python
class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        n = len(digits)
        i = n - 1
        while i >= 0 and digits[i] == 9:
            i -= 1
        if i < 0:
            return [1] + [0] * n
        digits[i] += 1
        for j in range(i + 1, n):
            digits[j] = 0
        return digits
```

- **思路**：定位「最右侧的非 9 位」，它 +1，其后全部置 0。
- **优点**：概念清晰，和链表版「给单链表加一」的 `O(n)` 一次遍历技巧同源（见下节）。
- **缺点**：需要两次遍历（找位置 + 清后缀），而推荐解法在遍历中顺手完成，代码更短。

### 4.4 解法 D：递归

```python
class Solution:
    def plusOne(self, digits: List[int], i: int = -1) -> List[int]:
        # 仅作教学演示：递归深度 = 末尾连续 9 的个数
        if -i > len(digits):
            return [1] + digits
        if digits[i] < 9:
            digits[i] += 1
            return digits
        digits[i] = 0
        return self.plusOne(digits, i - 1)
```

- **缺点**：全 9 时递归深度为 `n`，Python 默认递归上限 1000，输入较长时有 `RecursionError` 风险；且函数签名被污染。**不推荐**。

### 4.5 对比总结

| 解法 | 时间 | 额外空间 | 适用场景 | 评价 |
|---|---|---|---|---|
| **逆序原地进位（推荐）** | `O(n)` | `O(1)` | 本题标准解 | 简洁、无溢出、可提前返回 ✅ |
| 转整数 +1 | `O(n)` | `O(n)` | 仅 Python 小数据 | 语言相关、有溢出/位数限制风险 ❌ |
| 显式 carry | `O(n)` | `O(1)` | 通用大数加法 | 可扩展性好，对本题偏重 |
| 找最后非 9 位 | `O(n)` | `O(1)` | 链表版加一 | 思路对链表题很有用 |
| 递归 | `O(n)` | `O(n)` 栈 | 教学 | 有栈溢出风险 ❌ |

## 5. 同类题拓展

这一族题的核心模板就一句话：**「从低位向高位遍历，处理进位/借位」**。掌握后可以串起一串题：

### 5.1 同模板直接套用

| 题目 | 差异点 | 关键思路 |
|---|---|---|
| **369. 给单链表加一**（Plus One Linked List） | 链表单向，无法从尾部回退 | ① 反转 → 加一 → 反转；② 递归（栈）从尾部处理；③ 哨兵头 + 记录「最右侧非 9 节点」，最后把该节点 +1、其后全置 0，若不存在则哨兵 +1。③ 是最优 `O(n)` 一次遍历 |
| **989. 数组形式的整数加法** | 两个数组相加，其中一个可能是普通整数 | 双指针从尾部 + `carry`，结果用列表倒序收集 |
| **2. 两数相加** | 链表、**逆序**存储 | 天然从低位开始，直接双指针 + `carry` |
| **445. 两数相加 II** | 链表、**正序**存储 | 用两个栈把链表倒出来，再走 `2` 的模板 |
| **415. 字符串相加** | 字符串，长度可达 `10^4` | 双指针从尾部 + `carry`，`chr(ord('0') + d)` 拼接 |
| **67. 二进制求和** | 二进制 | 同上，只是 `% 2` / `// 2` |
| **43. 字符串相乘** | 乘法 | 「竖式乘法 + 字符串加法」的组合，是加一模板的升级版 |

### 5.2 变体追问（面试高频）

1. **不允许修改输入数组怎么办？**
   ```python
   res = digits[:]        # O(n) 拷贝
   # 后续逻辑完全不变
   ```

2. **数组是低位在前（小端序）怎么办？**
   进位从 `digits[0]` 开始，但「全 9 时要扩容」就变成**头部插入**。推荐用 `collections.deque` 做 `appendleft(1)`，均摊 `O(1)`。

3. **改成「减一」？**
   借位逻辑：从末位找第一个 `> 0` 的位减 1，其后全部置 9；若结果是 `[0, ...]` 需去掉前导零（例如 `[1,0,0] - 1 = [0,9,9]`，要再裁剪成 `[9,9]`）。**注意前导零裁剪**是减一比加一多出来的坑。

4. **改成「加 k」或「加任意大数」？**
   就退化为通用大数加法：显式 `carry`，`carry` 可能大于 1。

5. **改成任意进制 `base`？**
   ```python
   def plus_one_base(digits: List[int], base: int = 10) -> List[int]:
       for i in range(len(digits) - 1, -1, -1):
           if digits[i] + 1 < base:   # 注意：判断条件是 base - 1 才是满位
               digits[i] += 1
               return digits
           digits[i] = 0
       return [1] + digits
   ```

6. **数组长度上百万、无法整体载入内存？**
   从后往前流式读取（如反向读文件块），找到第一个非 9 的位置即可；因为期望只需检查常数个元素，实际 I/O 量可以做到很小。

## 6. 一句话总结

> 「加一」的唯一难点是**末尾连续的 9**。逆序遍历，遇到 `< 9` 就 `+1` 返回；一路全 9 则整体置 0 并在前面补 `1`。时间 `O(n)` / 最好 `O(1)`，额外空间 `O(1)`，且天然规避了整数溢出——这正是它比「转整数」更值得写进面试答案的原因。
