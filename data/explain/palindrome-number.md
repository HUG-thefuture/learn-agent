# 力扣 9. 回文数 — 题解讲解

## 1. 思路推导

### 1.1 先把"一定不是回文"的情况排掉

题面已经给了两条约定，先无脑排除：

| 情况 | 例子 | 原因 |
|---|---|---|
| 负数 | `-121` | 符号在最左，镜像后跑到最右变成 `121-`，不成数 |
| 非零且末位为 0 | `10`、`1200` | 回文要求首尾对称，而最高位不可能是 0 |
| `0` | `0` | 特例：它是回文，**不能被上一条误杀**，故判尾零时必须加 `x != 0` |

### 1.2 核心观察：回文 = 前半段 与 后半段的反转 相等

最朴素的做法是"把整个数反转再比较"，但它有两个毛病：

1. **溢出风险**：`2147483647` 反转后超出 32 位整数范围（Java/C++ 需要 `long long`）。
2. **做了无用功**：只比较一半就够了，反完整个数多花一倍计算。

所以我们**只反转后一半**，让两个变量相向而行：

- `x`：不断 `// 10`，代表"还没处理的前半部分"；
- `rev`：不断 `rev * 10 + x % 10`，代表"已处理的后半部分的反转值"。

当 `rev >= x` 时就说明走过了中点，循环结束。

### 1.3 结束时怎么判

以两个例子走一遍：

```
1221（偶数位）                12321（奇数位）
x=1221 rev=0                  x=12321 rev=0
x=122  rev=1                  x=1232  rev=1
x=12   rev=12  → 停止          x=123   rev=12
                              x=12    rev=123 → 停止
12 == 12  ✅                   中间那位 3 落在 rev 里，剥掉：123//10 = 12
                              12 == 12  ✅
```

于是终判是：`x == rev`（偶数位）**或** `x == rev // 10`（奇数位）。

### 1.4 ⚠️ 本题最大的坑：尾零

如果不做 1.1 的尾零特判，`10` 会这样走：

```
x=10 rev=0 → x=1 rev=0 → x=0 rev=1 → 停止
判 x == rev//10 →  0 == 0  → 返回 True ❌
```

因为"反转一半"的终止条件是 `x > rev`，对末尾带 0 的数会一路把 0 反到 `rev` 里，导致长度错位后误判。所以 `x % 10 == 0 and x != 0` 这一句**不能省**。

## 2. 推荐解法与代码（Python）

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        # 负数：符号位翻转后位置不同，必不是回文
        # 非零且末位为 0：最高位不可能是 0，必不是回文
        # （这一句同时避免了下面"半反转"对 10/100 的误判）
        if x < 0 or (x % 10 == 0 and x != 0):
            return False

        rev = 0  # 已反转的"后半部分"
        # 只反转一半：rev 追上或超过剩余部分时停止，天然规避整型溢出
        while x > rev:
            rev = rev * 10 + x % 10
            x //= 10

        # 偶数位：两半完全相等；奇数位：rev 多出正中间那一位
        return x == rev or x == rev // 10


if __name__ == "__main__":
    # 覆盖：正例、负数、尾零、单数字、奇数/偶数位、非回文、int32 上界
    cases = [
        (121, True), (-121, False), (10, False), (0, True),
        (1, True), (11, True), (1221, True), (12321, True),
        (123, False), (1000021, False), (2147483647, False),
    ]
    for x, want in cases:
        got = Solution().isPalindrome(x)
        assert got == want, f"x={x}: got {got}, want {want}"
    print("all passed")
```

关键点回顾：
- `while x > rev` 而不是 `while x != 0`——这正是"只走一半"的来源；
- `0` 能正常走完整流程并返回 `True`，无需额外分支；
- 全程只有两个整型变量，无额外容器，不存在内存泄漏面。

## 3. 复杂度分析

设 `n = |x|`，其十进制位数为 `d = ⌊log₁₀ n⌋ + 1`。

| 维度 | 结论 | 说明 |
|---|---|---|
| 时间 | `O(d) = O(log n)`，且常数约为朴素做法的一半 | 每轮迭代剥掉一位，最多 `⌈d/2⌉` 轮，每轮 O(1) |
| 空间 | `O(1)` | 仅 `x`、`rev` 两个整型 |

补充：Python 的整数是大整数对象，乘除法本身有位宽开销，但本题输入是 32 位整数（至多 19 位十进制），可视为常数，实际性能与字符串解法几乎无差；面试中强调 `O(1)` 空间才是加分项。

## 4. 其他解法对比

### 4.1 转字符串反转（工程首选，但不满足"进阶要求"）

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0:
            return False
        s = str(x)
        return s == s[::-1]
```

代码最短、不易错。代价是 `O(d)` 额外空间，且题目进阶要求"不将整数转为字符串"。

### 4.2 完全反转数字（本题技巧的"退化版"）

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0:
            return False
        n, rev = x, 0
        while n:
            rev = rev * 10 + n % 10
            n //= 10
        return rev == x   # Python 无溢出；C++/Java 需 long long 或提前剪枝
```

好处是**不需要尾零特判**（`10 → rev=1 ≠ 10`，自然判错）；坏处是溢出与多做一半工作。

### 4.3 数学"双指针"：首尾逐位比较（`O(1)` 空间，天然免疫尾零）

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0:
            return False
        div = 1
        while x // div >= 10:      # 找到与 x 同量级的 10 的幂
            div *= 10
        while x > 0:
            if x // div != x % 10: # 比较首尾
                return False
            x = (x % div) // 10    # 剥掉首尾两位
            div //= 100
        return True
```

思路直观，但每轮要做两次除法+取模，常数比"反转一半"大；且 `div` 的初始化需要额外一轮。

### 4.4 横向对比

| 解法 | 时间 | 空间 | 优点 | 缺点 / 适用 |
|---|---|---|---|---|
| **反转一半**（推荐） | `O(log n)`（≈一半） | `O(1)` | 无溢出、提前终止、满足进阶 | 必须处理尾零陷阱 |
| 转字符串 | `O(log n)` | `O(log n)` | 最短、最不易错 | 不满足"不用字符串"的进阶 |
| 完全反转 | `O(log n)` | `O(1)` | 无需尾零特判 | 有溢出风险，多算一半 |
| 首尾逐位比较 | `O(log n)` | `O(1)` | 无需特判，逻辑对称 | 常数较大，`div` 计算易错 |

**结论**：面试首选"反转一半"；追求可读性/大数场景（超 64 位）可直接用字符串双指针。

## 5. 同类题拓展

按技巧族归类，便于串联复习：

**A. 同一"取位/拼位"技巧**

- **7. 整数反转**：与本题同源，重点在反转后的溢出判断（本题的"只反一半"就是它的溢出规避手段）。
- **8. 字符串转换整数 (atoi)**：逐位解析 + 边界钳制，同样考"数字位处理"的细节功夫。

**B. 回文的链表版**

- **234. 回文链表**：快慢指针找中点 → 反转后半段 → 比较 → （可选）再反转恢复。与本题共享"只处理一半"的核心思想，且额外考资源恢复（不破坏入参）。

**C. 字符串/数组双指针**

- **125. 验证回文串**：双指针跳过非字母数字，注意大小写归一。
- **680. 验证回文串 II**：失配时分别尝试跳过左/右字符，课代表级"分情况一次"。
- **面试题 01.04 / 266. 回文排列**：用计数/奇偶性判断，与"逐位对称"是同一性质的不同入口。

**D. 回文子串（DP / 中心扩展 / Manacher）**

- **5. 最长回文子串**：中心扩展 `O(n²)`、Manacher `O(n)`。
- **647. 回文子串**：计数版，中心扩展比 DP 更好写。
- **131. 分割回文串**：回溯 + 预计算回文表（区间 DP），"判定回文"作为子过程复用。

**E. 构造型回文**

- **479. 最大回文数乘积**：从高位构造回文再判因子。
- **866. 回文素数**：构造回文 + 素性判定，考"剪枝与数学性质"（偶数位回文必被 11 整除）。

一句话总结本题的方法论：**先排除不可能的输入（负数、尾零），再抓住"镜像对称"这一性质，只处理一半并给出奇偶两种终结条件**——这套模板可以平移到链表、字符串、数组等一切回文问题。
