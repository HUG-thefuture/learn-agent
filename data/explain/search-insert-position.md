# 力扣 35. 搜索插入位置 — 题解讲解

## 1. 思路推导

### 1.1 先把问题“翻译”一遍

题目要求：在**升序无重复**数组 `nums` 中找 `target`。

- 找到了 → 返回它的下标；
- 没找到 → 返回它**按顺序插入**的位置，也就是**第一个大于 `target` 的元素的下标**。

把这两种情况合并，其实就是一个问题：

> **找到第一个 `>= target` 的元素的下标**（即 `lower_bound`）。

- 若该元素存在且等于 `target`，就是我们要找的位置；
- 若第一个 `>= target` 的元素比 `target` 大（或数组遍历完了），那就是插入位置。

举几个例子验证这个等价关系：

| nums | target | 第一个 `>= target` 的下标 | 答案 |
|---|---|---|---|
| `[1,3,5,6]` | 5 | 2（nums[2]=5） | 2 |
| `[1,3,5,6]` | 2 | 1（nums[1]=3） | 1 |
| `[1,3,5,6]` | 7 | 不存在 → n=4 | 4 |
| `[1,3,5,6]` | 0 | 0（nums[0]=1） | 0 |
| `[]` | 5 | 不存在 → 0 | 0 |

所以本题**不需要分“找到 / 没找到”两种情况写代码**，只要老老实实求 lower_bound，一个返回值就覆盖了全部边界。

### 1.2 为什么可以二分

暴力做法是从左往右扫，遇到第一个 `>= target` 就返回，时间 O(n)。但这浪费了“数组有序”这个信息。

关键性质：对任意下标 `mid`，

- 若 `nums[mid] < target`，则答案**一定在 `mid` 右边**（`mid` 及其左边都不可能是第一个 `>= target` 的位置）；
- 若 `nums[mid] >= target`，则答案**一定在 `mid` 或 `mid` 左边**。

每次判断都能**排除掉一半**的候选区间，这正是二分的前提。于是 O(n) → O(log n)。

### 1.3 写出二分的关键：先定义“循环不变量”

很多人二分写错，根源不在逻辑，而在**区间定义前后不一致**。建议动手前先声明清楚：

> **不变量**：答案一定落在区间 `[left, right]`（或 `[left, right)`）内。

然后 `while` 条件、`mid` 的更新、返回值，都必须与这个区间定义自洽。

下面给两个最常用的模板，选一个固定下来用就行。

## 2. 推荐解法与代码（Python）

### 解法 A：左闭右开区间 `[left, right)`（推荐）

这是最贴近 `lower_bound` 语义的写法，**无需特判、无 `-1` 干扰**。

```python
from typing import List


class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        # 不变量：
        #   [0, left)    中的元素全部 <  target
        #   [right, n)   中的元素全部 >= target
        #   答案始终落在 [left, right) 内
        left, right = 0, len(nums)          # 注意 right 取 n，是"开区间"

        while left < right:                 # 区间为空时退出
            mid = left + (right - left) // 2
            if nums[mid] < target:
                left = mid + 1              # mid 已确定小于 target，舍去
            else:
                right = mid                 # mid 可能是答案，保留

        # 退出时 left == right，即第一个 >= target 的下标
        return left
```

**为什么 `right = len(nums)` 而不是 `len(nums) - 1`？**
因为 `right` 是开区间端点，代表“候选区的右边界之外”。当 `target` 比所有元素都大时，答案就是 `n`，这个“虚拟下标”必须能被表示出来。若写成 `n - 1`（左闭右闭），则需要额外的 `-1/+1` 处理与返回值约定，反而更绕。

**手工模拟** `nums = [1,3,5,6], target = 2`：

| 轮次 | left | right | mid | nums[mid] | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 5 >= 2 | right = 2 |
| 2 | 0 | 2 | 1 | 3 >= 2 | right = 1 |
| 3 | 0 | 1 | 0 | 1 < 2 | left = 1 |
| 退出 | 1 | 1 | — | — | 返回 1 ✓ |

### 解法 B：左闭右闭区间 `[left, right]`

习惯 `<=` 写法的人可以用这个，注意返回值是 `left`（不是 `right`）。

```python
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1      # 闭区间 [left, right]

        while left <= right:                # 区间非空
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid                  # 命中，直接返回
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1

        # 退出时 left == right + 1，left 即第一个 > target 的下标
        # 也是 target 的插入位置
        return left
```

模拟 `nums = [1,3,5,6], target = 7`：`left` 依次 0→2→3→4，`right` 停在 3，退出返回 4 = n ✓。

两种写法**时间复杂度完全一致**，A 更短、更少分支，B 更符合“命中就返回”的直觉。面试时建议直接用 A，因为它是 `bisect_left` 的同款语义，可迁移性最强。

### 解法 C：直接用库（工程/比赛中）

```python
import bisect

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        return bisect.bisect_left(nums, target)
```

`bisect_left` 返回的就是“第一个 `>= target` 的下标”，C 实现，速度最快。但**一面时不要直接甩这一行**，面试官考的是你能不能手写二分，可以把 A 作为主答案，再补充“实际工程中我会用 `bisect_left`”。

## 3. 复杂度分析

| 维度 | 值 | 说明 |
|---|---|---|
| 时间 | **O(log n)** | 每轮区间长度至少减半，最多 ⌈log₂(n+1)⌉ 轮；每轮 O(1) |
| 空间 | **O(1)** | 仅 `left/right/mid` 三个变量，无递归栈、无额外容器 |

细节说明：

- **循环次数**：区间长度从 `n` 收缩到 0，每轮至少减 1 且通常减半，最坏 ⌈log₂(n+1)⌉ 次。`n = 1e9` 时也只需约 30 次比较。
- **`mid` 计算**：Python 整数无溢出，直接 `(left + right) // 2` 也安全；但**Java/C++ 必须写 `left + (right - left) / 2`**，否则 `left + right` 在大数组下会整型溢出成负数。养成这个习惯，跨语言迁移不出错。
- **无内存泄漏风险**：全局部变量、无分配对象、无递归，天然安全（对比递归二分会产生 O(log n) 的调用栈）。

## 4. 其他解法对比

| 解法 | 时间 | 空间 | 是否满足要求 | 评价 |
|---|---|---|---|---|
| 线性扫描 | O(n) | O(1) | ❌ | 最简单，可作为暴力 baseline 口头提出，但**不满足题目的 O(log n)** |
| 左闭右开二分（解法 A） | O(log n) | O(1) | ✅ | **推荐**，代码最短、分支最少、与 `lower_bound` 语义一致 |
| 左闭右闭二分（解法 B） | O(log n) | O(1) | ✅ | 等价，多一个 `==` 分支；注意 `while <=` 与 `right = n-1` 必须配套 |
| `bisect_left` | O(log n) | O(1) | ✅ | 工程首选，但面试需能手写 |
| 递归二分 | O(log n) | **O(log n)** | ✅ | 空间变差，且无尾递归优化时有栈溢出风险，不推荐 |
| 二分“答案”框架 | O(log n) | O(1) | ✅ | 把下标当答案域二分，与 A 本质相同，是通用套路（见下） |

### 关于“二分答案”通用框架

其实所有二分都可以套一个壳子——**在答案值域上二分，写一个 `check(x)` 单调判定函数，求第一个 `check(x) == True` 的位置**：

```python
def binary_search_first_true(lo: int, hi: int, check) -> int:
    """在 [lo, hi] 中找第一个满足 check(x) 为 True 的位置；保证至少有一个解。"""
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if check(mid):
            hi = mid          # mid 可行，答案在 mid 或更左
        else:
            lo = mid + 1      # mid 不可行，答案在右侧
    return lo
```

本题中 `check(i) = nums[i] >= target`，答案域是 `[0, n]`（注意含虚拟下标 `n`），于是就是解法 A。这个框架在下面的“二分答案”类题目里几乎原封不动就能用。

### 常见踩坑清单

1. **`while` 条件与区间定义不匹配**：左闭右闭配 `<=`，左闭右开配 `<`，混用必死循环或漏判。
2. **更新端点忘 ±1**：左闭右开时 `right = mid`（不 -1），左闭右闭时 `right = mid - 1`。
3. **返回值写错**：左闭右闭版本要返回 `left`，返回 `right` 会小 1。
4. **空数组**：`nums = []` 时 A、B 都返回 0，天然正确，无需特判（这正是“等价转化”带来的好处）。
5. **`target` 比所有元素都大**：A 返回 `n`，在合法下标范围外，但题目要求的正是这个值——不要在最后做 `min(left, n-1)` 之类的“保护”。

| 题目 | 要点 |

**识别信号**：题目出现“**最大值最小化 / 最小值最大化 / 最小的可行 X / 第 k 个**”这类措辞时，多半是二分答案；先写出 `check(x)` 并确认它具有单调性（`x` 可行 ⇒ 更大的 `x` 也可行，或反之），再套 `binary_search_first_true`。

### 5.4 一句话总结

> 本题的本质是 **`lower_bound`**：求“第一个满足 `nums[i] >= target` 的下标”。
> 记住三件事——**先定义区间不变量、端点更新与区间定义严格配套、答案落在 `[0, n]` 且 `n` 是合法返回值**，这题就再也不会错了。
