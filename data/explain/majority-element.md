# LeetCode 169. 多数元素 · 题解讲解

> 题目：给定长度为 n 的数组 `nums`，返回出现次数 **严格大于 ⌊n/2⌋** 的元素。题目保证该元素一定存在。
> 要求：尝试 O(n) 时间、O(1) 空间的解法。

---

## 1) 思路推导

### 1.1 从朴素解法出发

| 思路 | 关键点 | 瓶颈 |
|---|---|---|
| 双重循环统计 | 每个元素数一遍 | O(n²) |
| 哈希表计数 | 一次遍历边计数边比较 | 时间 O(n)，但**空间 O(n)** |
| 排序后取中位 | 众数必然占据下标 n//2 | O(n log n) |
| 分治 | 左右两半的众数必有一个是整体的众数 | O(n log n) |

要突破到 **O(1) 空间**，必须找到只依赖「数量过半」这一强条件、不需要额外存储的性质。常见做法是排序法（O(n log n)）和摩尔投票法（O(n)）。

### 1.2 关键观察：「过半」意味着一个打一个也能赢

设 `m` 出现 `c` 次，则 `c > n/2`，也就是

```
c > (n - c)     // 多数元素的个数 > 所有其他元素个数之和
```

**推论**：把 `m` 和任意一个非 `m` 的元素配对抵消，`m` 依然会剩下。即使用最强的对抗方式（其他所有元素联合起来一对一消耗 `m`），`m` 也一定还有剩余。

### 1.3 抵消过程的严格化（引理）

> **引理**：若 `m` 是长度 n 的数组的严格多数，任取两个**不同**元素删除后，`m` 仍是新数组（长度 n-2）的严格多数。

**证明**：设删除后 `m` 出现 `c'` 次，最多删掉一个 `m`，故 `c' ≥ c - 1 > n/2 - 1 = (n-2)/2`。
（若删的两个都不是 `m`，则 `c' = c > n/2 > (n-2)/2`，更显然。）∎

**反复应用该引理**：不断「找两个不同元素删掉」，直到数组只剩同一种元素（或只剩 1 个元素）。由引理，此时剩下的元素必然是 `m`。**这就是摩尔投票法的本质。**

### 1.4 用栈模拟抵消 → 压缩成两个变量

抵消过程可以这样用栈模拟：

- 当前元素与栈顶相同 → 入栈；
- 与栈顶不同 → 弹出栈顶（两者抵消）；
- 栈为空 → 入栈。

**关键性质**：这个栈里永远只装着**同一种元素**。于是「栈内容」只需要 `candidate`（栈里是什么）和 `count`（栈里有几个）就能表示：

```
遍历 x：
  count == 0        → candidate = x, count = 1   （栈空，x 入栈）
  x == candidate    → count += 1                 （同种元素入栈）
  否则              → count -= 1                 （抵消掉一个）
```

遍历结束时，`candidate` 就是答案（题目保证存在，无需二次验证）。

> 一句话记法：**不同的元素两两抵消，最后活下来的就是多数元素。**

## 2) 推荐解法与代码（Python）

### 2.1 标准解法：Boyer-Moore 摩尔投票

```python
from typing import List


class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate = None   # 当前"候选"元素（栈里装的是什么）
        count = 0          # 候选元素的"未被抵消数量"（栈里装了几个）

        for x in nums:
            if count == 0:
                # 栈空：把 x 作为新的候选压栈
                candidate, count = x, 1
            elif x == candidate:
                # 同种元素：压栈
                count += 1
            else:
                # 不同元素：抵消掉一个候选
                count -= 1

        # 题目保证多数元素一定存在，此时 candidate 即为答案
        return candidate
```

**易错点提醒**

- `count == 0` 的判断必须放在最前面（等价于栈空时直接入栈），否则 `candidate` 可能还是上一轮的旧值。
- `count` 减到 0 时**不要**立刻换候选，而是等下一轮由 `count == 0` 分支来换 —— 这样逻辑更简洁，也避免了「减到 0 后当前元素到底算不算候选」的歧义。
- 本题保证答案存在，所以可以省略验证；但工程代码或面试中若**不保证存在**，必须补一次线性校验（见 2.2）。

### 2.2 健壮版（不保证存在时二次校验）

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate, count = None, 0
        for x in nums:
            if count == 0:
                candidate, count = x, 1
            elif x == candidate:
                count += 1
            else:
                count -= 1

        # 第二遍线性扫描确认；不满足则返回 -1（对应面试题 17.10）
        return candidate if nums.count(candidate) > len(nums) // 2 else -1
```

`list.count` 是 O(n)，因此总复杂度仍是 **O(n) / O(1)**。

### 2.3 可运行的测试

```python
if __name__ == "__main__":
    s = Solution()
    cases = [
        ([3, 2, 3], 3),
        ([2, 2, 1, 1, 1, 2, 2], 2),
        ([1], 1),                  # 单元素
        ([1, 1, 2], 1),            # 多数在头部
        ([1, 2, 2], 2),            # 多数在尾部（count 会反复归零）
        ([1, 1, 1, 2, 3], 1),      # 多个不同元素干扰
    ]
    for nums, expect in cases:
        got = s.majorityElement(nums)
        assert got == expect, f"{nums}: got {got}, expect {expect}"
    print("all passed")
```

## 3) 复杂度分析

| 指标 | 值 | 说明 |
|---|---|---|
| 时间 | **O(n)** | 一次遍历，每个元素 O(1) 操作；验证版再扫一遍仍为 O(n) |
| 空间 | **O(1)** | 只用两个变量 `candidate`、`count`，与 n 无关 |
| 输入是否修改 | 否 | 不排序、不建表，对只读流式数据友好 |

**补充：为什么这是下界？** 任何正确算法都必须至少看一遍数组（否则漏掉的元素可能是多数），故 Ω(n) 时间是下界；而 Ω(1) 空间已被本算法达到，因此 **O(n)/O(1) 是这个问题的理论最优**（在比较模型下）。

## 4) 其他解法对比

| 解法 | 时间 | 空间 | 优点 | 缺点 / 适用场景 |
|---|---|---|---|---|
| **摩尔投票**（推荐） | O(n) | **O(1)** | 最优；适合流式 / 超大数据 / 只读输入 | 依赖「超过一半」这一强条件；不保证答案存在时需二次校验 |
| 哈希表计数 | O(n) | O(n) | 最通用，可直接推广到「出现次数 > n/k」「Top-K 频率」 | 额外内存；数据量极大或内存受限时不合适 |
| 排序取中位 | O(n log n) | O(1)（原地）/ O(n)（`sorted` 新建） | 代码最短：`sorted(nums)[n//2]` | 修改/复制输入；比投票慢一个 log；对超大数组不友好 |
| 分治 | O(n log n) | O(log n) | 思想漂亮，是「区间合并」类问题的模板（见 1157 题） | 常数大、实现长，实际不如投票 |
| 随机化抽样 | 期望 O(n) | O(1) | 实现极短，期望线性 | **概率**正确；需「存在多数」的前提；面试中通常不作为主答案 |
| 按位统计 | O(32n) = O(n) | O(1) | 只做位运算，适合并行 / 硬件实现 | 只适用于非负整数（负数要处理符号位 / 补码），且常数 32 |

**选型建议**

- 面试主答：**摩尔投票**（要能讲清「两两抵消」的正确性证明，这是加分点）。
- 快速手写 / 允许改输入：排序取中位。
- 需要统计多个候选、或出现次数阈值是 n/k 且分布未知：哈希表或广义投票 + 校验。

## 5) 同类题拓展

### 5.1 直接同源：面试题 17.10. 主要元素

与本题几乎相同，但**不保证存在**，不存在返回 `-1` → 直接用 2.2 的「投票 + 二次校验」版本。这是最该一起刷的一题，帮你养成「投票后必须验证」的直觉。

### 5.2 升级版：229. 求众数 II（出现次数 > ⌊n/3⌋）

性质：出现超过 n/3 的元素**最多只有 2 个**。于是开两个候选、两个计数器 —— **广义 Boyer-Moore**（把「两两抵消」变成「三三抵消」）。

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        cand1 = cand2 = None
        cnt1 = cnt2 = 0

        for x in nums:
            if x == cand1:            # 先匹配已有候选（顺序不能反）
                cnt1 += 1
            elif x == cand2:
                cnt2 += 1
            elif cnt1 == 0:
                cand1, cnt1 = x, 1
            elif cnt2 == 0:
                cand2, cnt2 = x, 1
            else:                     # 三个不同元素互相抵消
                cnt1 -= 1
                cnt2 -= 1

        # 本题不保证存在，必须验证
        return [c for c in {cand1, cand2}
                if c is not None and nums.count(c) > len(nums) // 3]
```

**推广结论**：求「出现次数 > ⌊n/k⌋」的元素，候选最多 k-1 个，用 k-1 组 `(candidate, count)` 即可，时间 O(nk)、空间 O(k)；结果仍需校验。这正是流式场景下的 **Misra-Gries 算法**。

### 5.4 本题能带走的三个可迁移思想

1. **「抵消 / 配对」是处理多数问题的通用方法**：多数元素之所以能存活，是因为它的数量超过了所有对手之和。
2. **候选-计数二元组可以合并**：`(cand, cnt)` 支持结合律的合并（`merge` 时同则加、异则减），所以能塞进线段树 / 分治结构（1157）。
3. **投票只保证「候选」正确，不保证「答案」存在**：阈值解（> n/k）与存在性校验要分开想，这是 229、17.10 的最大问题。
